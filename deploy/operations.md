# 后台运行与更新

VoidPlayer 默认是便携程序：解压到可写文件夹，直接运行 `./voidplayer`，运行数据集中在程序旁边的 `data/`。不需要 `/opt/voidplayer/current`、`/var/lib/voidplayer`、独立账号或系统服务。

## 普通使用

```sh
cd /你的/VoidPlayer目录
./voidplayer
```

Windows 使用 `./voidplayer.exe`。Ctrl+C 停止。指定媒体目录可加 `--folder /媒体目录`，也可以启动后在 `/admin` 中添加。首次自动生成配置，后续沿用。

## 可选：关闭终端后继续运行

Linux / macOS 可以在程序目录运行：

```sh
mkdir -p data
./voidplayer --check
nohup ./voidplayer > /dev/null 2>&1 &
```

先检查配置，再后台启动。服务运行日志自动写入 `data/runtime-logs/`（自定义数据目录时跟随 `dataDir`），默认按天或 10 MiB 切段 gzip，保留 60 天、最多 256 MiB；无需再把终端镜像无界追加到 `console.log`。配置加载之前的错误需前台运行查看。停止时对进程发送 SIGINT 或 SIGTERM，等待日志排空、压缩及进程退出后再备份或升级。旧手动创建的 `console.log` 不自动清理。策略与 macOS 用户服务迁移见[日志留档](../docs/server-logging.md)。

Windows 可以直接保持程序窗口开启；若需要登录后自动运行，可在任务计划程序中选择该目录内的 `voidplayer.exe`。系统服务、专用账号和外置数据目录都属于可选的运维方式，不是程序运行的前提。

## 只发布前端

适用于已经支持版本保留的 VoidPlayer 服务。保持原域名和端口；播放器、管理页以及已安装的 PWA 继续使用原有地址。

源码部署在仓库根目录执行：

```sh
npm run build
npm run publish:frontend -- dist
```

第一条命令在独立目录生成并校验候选构建，成功后更新便携产物 `dist/`。第二条命令读取服务配置，将候选构建发布到该服务的 `dataDir/frontend-releases/`。若运行服务时指定了自定义配置，请在发布时也指定，例如 `npm run publish:frontend -- dist --config /srv/voidplayer/config.json`。首次启动 `npm run serve` 会自动发布随附构建。

独立包部署可把新包解压到另一个目录，再从**当前运行的程序目录**执行：

```sh
./voidplayer --publish-frontend /path/to/new-package/dist
```

Windows 使用 `voidplayer.exe`。若服务指定了 `--data-dir`，发布命令须指向同一目录。命令打印已发布的 `buildId` 后，可以在服务的 `/build-info.json` 核对当前入口。前端热发布适用于与当前后端 API 兼容的版本；同时变更 API、数据库或服务端解码核心时，按下一节升级程序。

### 生效、保留与回退

- 每次生产构建都有独立的 `buildId`。候选目录中的 `frontend-release.json` 记录逐文件 SHA-256。发布先校验并安装全部文件，再原子替换 `current.json`。复制失败或校验不通过时，线上入口继续使用上次成功发布的构建。
- 普通网页下次打开时取得新入口。已有窗口仍可按原地址加载它的脚本、Worker 和 WASM。PWA 在后台准备完整版本，旧受控窗口结束后再激活更新；发布不会主动刷新正在评审的窗口。
- 支持更新提示的播放器在前台约每 10 秒、回到窗口时也会检查服务公布的前端版本。发现新版本会显示警告，右上角状态灯变为琥珀色刷新按钮。关闭提示仍可继续工作；同版本的服务重启只恢复连接。旧版页面首次需要在结束评审后重新打开一次，才具备此提示。
- 点击「保存现场并刷新」先检查片源可读取、标注已落盘，并将当前用户、当前窗口的工作区写入本机恢复记录。PWA 还会等目标离线资源就绪。刷新后自动恢复轨道、播放位置、标注、视口和面板；解码器和后台分析会重新初始化。播放或编辑中请先暂停并完成编辑。缺少持久读取授权的本地视频请继续在原窗口评审，或先导出工作区与原文件一起保管。已绑定服务器的工作区请先保存，再通过原工作区重新打开。
- 已有当前版本时，可用 `npm run publish:frontend -- /path/to/old/dist --retain` 补入完整历史构建，当前入口保持在线。
- 版本库保留最近三次不同构建，以及退出当前入口未满七天的构建。服务端使用的随包核心所在构建也保留。清理在后续发布时进行。相同内容的同路径文件在支持硬链接的文件系统上复用磁盘空间。
- 前端回退使用相同发布命令，传入保留的旧包 `dist/` 或 `dataDir/frontend-releases/<buildId>/`。回退只切换前端入口。日常应通过发布命令更新版本库；直接编辑其中的文件会同时影响共享这些文件的历史版本。
- 第一次从原地覆盖 `dist/` 的旧部署迁移时，先另存正在使用的完整旧 `dist/`。用新版程序先发布这份旧构建，再发布新版，即可为迁移前已打开的页面保留资源。旧版已生成 `build-info.json`、静态校验清单和离线 Worker 的产物支持导入；已经丢失的旧模块无法从新包还原。
- 若发布进程异常退出并留下 `dataDir/frontend-releases/.publishing`，先确认该数据目录没有正在发布的进程，再移除这个空锁目录并重试。构建进程的锁位于仓库 `.run/frontend-build/lock`，恢复方式相同。

## 备份和升级后端程序

1. 停止程序，确认进程已退出。
2. 备份整个 `data/`。其中包含配置、用户、评审、索引以及可能存在的 SQLite WAL/SHM 文件，不能只复制一个数据库主文件。
3. 解压新包，把原来的 `data/` 复制进去，再直接运行新程序。保留旧包与升级前备份便于回退。

搬动程序文件夹时，`data/` 和 `dist/` 随程序一起搬动；配置里引用的外部媒体路径需要仍然可访问。若显式使用了 `--data-dir`、`--config` 或自定义日志目录，请同时保留这些外置文件。

旧版程序可能无法读取升级后的数据库。回退时使用与旧程序匹配的备份。媒体视频本身由用户另行备份，不包含在工作区数据库里。

### 静态资源压缩与缓存

生产构建为脚本、样式、WASM 等资源生成 Brotli/gzip 文件和 `static-assets.json`。
服务端按 `Accept-Encoding` 选择经过 SHA-256 验证的表示；Range 请求读取原文件，媒体 API 仍使用原来的 Range 与 `no-store` 策略。
入口 HTML 使用 `no-cache` 并支持 ETag 条件请求；带内容哈希的资源使用一年 `immutable` 缓存。
WASM 及其加载脚本分别使用各自内容的 SHA-256 版本参数。旧请求从保留的构建中取匹配字节；所需版本已清理时返回 409。
构建校验压缩文件的哈希和解压结果。部署时把完整候选目录交给发布命令，运行中的服务会读取新的入口指针。
