# 后台运行与更新

VoidPlayer 默认是便携程序：解压到可写文件夹，直接运行 `./voidplayer`，运行数据集中在程序旁边的 `data/`。不需要 `/opt/voidplayer/current`、`/var/lib/voidplayer`、独立账号或系统服务。

## 普通使用

```sh
cd /你的/VoidPlayer目录
./voidplayer
```

Windows 使用 `./voidplayer.exe`。Ctrl+C 停止。指定媒体目录可加 `--folder /媒体目录`，也可以启动后在 `/admin` 中添加。首次自动生成配置，后续沿用。

## 可选：关闭终端后继续运行

Linux / macOS 可以在程序目录运行：

```sh
mkdir -p data
nohup ./voidplayer > data/console.log 2>&1 &
```

这里的 `console.log` 是上述命令显式创建的终端输出文件，程序本身不自动创建它。停止时对该进程发送 SIGINT 或 SIGTERM，确认退出后再备份或升级。长期运行时按需清理或轮转这个文件。

Windows 可以直接保持程序窗口开启；若需要登录后自动运行，可在任务计划程序中选择该目录内的 `voidplayer.exe`。系统服务、专用账号和外置数据目录都属于可选的运维方式，不是程序运行的前提。

## 备份和升级

1. 停止程序，确认进程已退出。
2. 备份整个 `data/`。其中包含配置、用户、评审、索引以及可能存在的 SQLite WAL/SHM 文件，不能只复制一个数据库主文件。
3. 解压新包，把原来的 `data/` 复制进去，再直接运行新程序。保留旧包与升级前备份便于回退。

搬动程序文件夹时，`data/` 和 `dist/` 随程序一起搬动；配置里引用的外部媒体路径需要仍然可访问。若显式使用了 `--data-dir`、`--config` 或自定义日志目录，请同时保留这些外置文件。

媒体索引和工作区当前均为 schema 2，旧版程序可能无法读取。回退时使用与旧程序匹配的备份。媒体视频本身由用户另行备份，不包含在工作区数据库里。
