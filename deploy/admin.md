# 服务管理

打开 `/admin`，或点击播放器右上方的服务状态灯在新标签页打开。管理页面与播放器共用外观偏好，改变亮暗或主题色会同步到已打开的管理页。

## 身份与权限

直接运行并从本机访问时，本机回环连接与回环 Host 都通过才拥有管理权限。远端沿用认证网关身份，并要求用户 ID 出现在管理员名单中：

```json
{
  "adminUsers": ["team.admin", "qa.tester"]
}
```

名单区分大小写，对应网关传来的真实用户 ID。也可用 `VOIDPLAYER_ADMIN_USERS=team.admin,qa.tester` 覆盖配置；设置为空字符串会撤销全部远端管理员。名单默认空，普通播放器用户不能访问管理 API。修改管理员配置后重启服务。不能通过浏览器自报身份或传入管理员字段获得权限。

所有管理写操作要求同源 Origin 和管理动作头。媒体根目录修改、日志删除由管理 API 执行；播放器仍可使用原有的媒体查询、读取与扫描刷新能力。主动上传日志仍由用户点击触发。

## 页面与数据

- **概览**：实际程序版本、运行时、运行时间、CPU、内存、HTTP 连接与请求数量，以及扫描/监听状态。CPU 以一个逻辑核为 100%，不是整机 CPU 占比；连接数包括保持连接。
- **媒体库**：编辑名称与服务器绝对路径、添加或移出目录、保存配置、校准或取消扫描，以及分页查看读取错误。新增路径暂时离线仍可保存，由扫描状态显示是否可用。
- **日志**：有界分页查看已收到的诊断日志，直接预览 JSON、下载，或确认删除。另可查看本次进程最近 200 条请求，完整运行日志仍由服务管理器/容器保存。后台轮询不会自动上传客户端日志。

根目录保存写回实际使用的 `voidplayer.config.json`，不创建另一份根目录配置。保留稳定 ID，原子替换配置文件；成功后立即重新校准索引。已开始的媒体字节流不主动中断。移出根目录不删除视频文件，后续新请求将无法再从该根读取。

配置保存带版本检查。另一个管理页面已保存时返回冲突，不覆盖较新的配置；外部编辑被检测到时暂停页面保存，重启服务重新载入后再编辑。`--folder` 临时覆盖的目录不在后台写回；使用 `--init` 创建正式配置后启动即可管理。配置所在目录必须可写。

新上传日志包含服务端生成的接收 ID、接收时间及真实用户 ID，客户端提交的同名信息会被覆盖。旧日志没有可靠接收信息时标为历史日志。日志不提供在线修改；读取与删除检查文件版本，文件改变时要求重新载入。删除只允许日志目录下的普通日志文件，不跟随符号链接。

## 存储离线与根目录绑定

每个网络挂载应单独配置为媒体根目录。服务记录根所在文件系统的类型；当 NFS/SMB 卸载后暴露出不同类型的本地空目录时，显示 `ESTORAGECHANGED`，保留索引并拒绝从该根提供新媒体请求。原文件系统恢复后，手动或周期校准会重新核对文件版本并恢复可用状态。实际文件删除且文件系统未变时仍正常校准，不把所有空目录都当成离线。

升级已有 schema 1 索引时，先通过至少一个版本未改变的原媒体建立绑定。存储未恢复或原库全部更换时，可能显示 `ESTORAGEUNVERIFIED`；服务不会把未核对的底层目录记成原库。恢复原挂载后重新校准。若是有意换库，可添加新根目录（新 ID）；明确修改既有根路径则允许迁移到新的文件系统，并重新核对文件版本。改名不会清除绑定。

这是基于操作系统文件系统类型的保护，不能识别同类型的另一块存储或藏在根目录下的独立子挂载；它也不是网络共享身份认证。类型编号与操作系统有关，跨系统迁移时需重新配置实际根路径或添加新的根。底层系统若只返回通用类型，仍主要依赖路径错误和文件版本检查。真实网络断线、挂载恢复和操作系统 I/O 超时仍需在目标存储上验收。

## 容器

在 `deploy/.env` 设置 `VOIDPLAYER_ADMIN_USERS`，与 `users.caddy` 中的账号一致，再重新创建 app 容器。

容器首次启动把镜像中的配置模板初始化到 `/data/voidplayer.config.json`。后台保存写入持久化 `app-data` 卷，程序目录和媒体挂载继续只读；后续镜像升级不覆盖这份配置。需要额外媒体根时，先在 Compose 中添加对应的只读挂载，再使用容器内路径在后台添加目录。

容器默认禁用日志上传。需要启用时，在持久化配置中将 `logsDir` 设为 `/data/logs` 并重启服务；日志与配置、索引一起备份。已有实例的配置若由外部 `--config` 指定，则继续使用该路径，后台仅在其父目录可写时允许保存。

## 主动测速

“测速”页面提供四个独立场景，只有点击“开始测试”才产生负载：

| 场景 | 读取/传输路径 | 结果含义 |
| --- | --- | --- |
| 下载吞吐 | 服务器随机内存数据 → 当前浏览器，单路 | 包含网关、TLS、网络与浏览器处理，不读取媒体磁盘 |
| 上传吞吐 | 当前浏览器随机数据 → 服务器，单路 | 数据接收后丢弃，不保存文件；按浏览器收到完成响应计时 |
| 存储读取 | 服务器重复读取所选媒体，单路，每块最多 1 MiB | 包含文件打开、版本校验和系统缓存；不是绕过缓存的磁盘物理带宽 |
| 四路媒体读取 | 四路同时读取同一所选媒体并传到浏览器，每块最多 1 MiB | 合计有效吞吐，包含存储、HTTP、网关、网络及浏览器连接调度 |

媒体从索引中搜索、分页选择，仅允许当前可读的非空媒体；不接受任意磁盘路径。读取到文件末尾后循环读取，文件版本改变会停止任务。四路请求会争用同一文件及系统缓存，不代表四块独立磁盘或全部客户端的承载上限。

时长可选 5/10/15 秒，数据量上限可选 64/256/1024 MiB；任一上限先到即停止，不自动提高负载。服务同时只允许一个任务，每个任务最多四路传输，防止多标签页叠加。发起者可以取消，页面关闭会尝试取消，服务器时限仍独立生效。取消停止新增读取；正在等待操作系统完成的存储 I/O 会显示“正在结束”，待句柄释放后才允许下一次任务。

结果显示实测 Mbps、MiB/s、已完成数据、实际耗时、并发数、媒体版本及结束原因。网络与四路测试使用发起浏览器的计时（包含请求往返）；浏览器尚未提交结果时，其他管理页标明仅有服务端计数。中断的上传块不算完成数据，下载按浏览器实际收到的字节统计。结果只保留本次进程最近一个任务，不保存历史测速记录，也不上传到外部服务。

本机回环、热缓存、小文件、TLS 终止位置与浏览器连接限制都会影响结果。比较前应保持文件、时长、上限和访问地址相同；这里不把短时测量当作机器的理论最大带宽。工作区的保存与冲突处理见下节。


## 服务器工作区

播放器“设置 → 工作区”提供主动保存、载入、另存副本、搜索与删除。文件导出/导入仍独立可用。工作区包含媒体服务地址、版本化的视频引用、标注、缩略图、播放位置与布局，不包含视频字节；选择本地文件的工作区仍须在载入时重新选择原文件。

- 普通网关用户只能列出、读取、修改和删除自己的工作区。管理员可在 `/admin` 的“工作区”中检视全部内容、改名、下载、删除，或在新播放器标签页打开继续编辑。
- 归属、创建时间、更新时间和最后编辑者由服务器生成，客户端不能通过正文中的同名字段冒充归属。管理员修改他人的工作区时，原归属不变，最后编辑者记录管理员；另存副本归属当前操作者。
- 新工作区使用随机 ID，初始版本为 1。更新/删除必须带当前版本 `If-Match`；过期请求返回 409，不覆盖新内容。播放器保留未保存的会话，并提供“载入服务器版本”或“另存副本”，不提供无条件覆盖。已删除的 ID 不能被旧保存请求复活。
- 数据存到本机数据目录的 `workspaces.sqlite`，与可重建的媒体索引分开。一次 SQLite 写操作同时提交内容、摘要和版本；页面不会因播放器操作自动上传。数据库仅保留当前版本，版本号用于冲突检测，不是完整历史版本或多人实时协作。
- 单个工作区最多 32 MiB（包含缩略图）；列表按 40 条分页，只取摘要。搜索/返回最新会重新查询，列表翻页期间的更新可能移到最新页。

升级与恢复时备份整个数据目录，包含工作区数据库及其 WAL/SHM；停机备份和恢复流程见 [后台运行与恢复](operations.md)。恢复后应实际打开工作区并检查媒体引用，不能仅检查数据库文件存在。服务器地址或媒体版本改变仍需按原有工作区规则重新连接；服务端保存不会绕过媒体访问权限。
