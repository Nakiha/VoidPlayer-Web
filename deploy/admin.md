# 服务管理

打开 `/admin`，或点击播放器右上方的服务状态灯在新标签页打开。管理页面与播放器共用外观偏好，改变亮暗或主题色会同步到已打开的管理页。

## 身份与权限

直接运行并从本机访问时，本机回环连接与回环 Host 都通过才拥有管理权限。远端沿用认证网关身份，并要求用户 ID 出现在管理员名单中：

```json
{
  "adminUsers": ["team.admin", "qa.tester"]
}
```

名单区分大小写，对应网关传来的真实用户 ID。也可用 `VOIDPLAYER_ADMIN_USERS=team.admin,qa.tester` 覆盖配置；设置为空字符串会撤销全部远端管理员。名单默认空，普通播放器用户不能访问管理 API。修改管理员配置后重启服务。不能通过浏览器自报身份或传入管理员字段获得权限。

所有管理写操作要求同源 Origin 和管理动作头。媒体根目录修改、日志删除由管理 API 执行；播放器仍可使用原有的媒体查询、读取与扫描刷新能力。主动上传日志仍由用户点击触发。

## 页面与数据

- **概览**：实际程序版本、运行时、运行时间、CPU、内存、HTTP 连接与请求数量，以及扫描/监听状态。CPU 以一个逻辑核为 100%，不是整机 CPU 占比；连接数包括保持连接。
- **媒体库**：编辑名称与服务器绝对路径、添加或移出目录、保存配置、校准或取消扫描，以及分页查看读取错误。新增路径暂时离线仍可保存，由扫描状态显示是否可用。
- **日志**：有界分页查看已收到的诊断日志，直接预览 JSON、下载，或确认删除。另可查看本次进程最近 200 条请求，完整运行日志仍由服务管理器/容器保存。后台轮询不会自动上传客户端日志。

根目录保存写回实际使用的 `voidplayer.config.json`，不创建另一份根目录配置。保留稳定 ID，原子替换配置文件；成功后立即重新校准索引。已开始的媒体字节流不主动中断。移出根目录不删除视频文件，后续新请求将无法再从该根读取。

配置保存带版本检查。另一个管理页面已保存时返回冲突，不覆盖较新的配置；外部编辑被检测到时暂停页面保存，重启服务重新载入后再编辑。`--folder` 临时覆盖的目录不在后台写回；使用 `--init` 创建正式配置后启动即可管理。配置所在目录必须可写。

新上传日志包含服务端生成的接收 ID、接收时间及真实用户 ID，客户端提交的同名信息会被覆盖。旧日志没有可靠接收信息时标为历史日志。日志不提供在线修改；读取与删除检查文件版本，文件改变时要求重新载入。删除只允许日志目录下的普通日志文件，不跟随符号链接。

## 容器

在 `deploy/.env` 设置 `VOIDPLAYER_ADMIN_USERS`，与 `users.caddy` 中的账号一致，再重新创建 app 容器。

容器首次启动把镜像中的配置模板初始化到 `/data/voidplayer.config.json`。后台保存写入持久化 `app-data` 卷，程序目录和媒体挂载继续只读；后续镜像升级不覆盖这份配置。需要额外媒体根时，先在 Compose 中添加对应的只读挂载，再使用容器内路径在后台添加目录。

容器默认禁用日志上传。需要启用时，在持久化配置中将 `logsDir` 设为 `/data/logs` 并重启服务；日志与配置、索引一起备份。已有实例的配置若由外部 `--config` 指定，则继续使用该路径，后台仅在其父目录可写时允许保存。

主动吞吐/存储/并发测量和可编辑工作区对象仍是 roadmap 后续交付，不将当前运行指标当作带宽测试结果。
