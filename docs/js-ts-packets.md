# JS H.264 TS packet adapter

Issue #63 starts with `TsPacketSource`: pinned Mediabunny 1.55.7 owns container/PES/AU demux and seeking, a small JS PES-header supplement preserves the original 90 kHz PTS/DTS, and existing `PacketTimeline`/packet decoders plus independent analysis consume the same records. Each consumer owns its reader, Input, cursor and cancellation. There is no WASM demux dependency in this adapter.

This stage is an adapter contract, not completed product migration. The default product router and persistent library protocol are unchanged. Browser presented-token/overlay checks, local/library product wiring, raw-clock negatives, full cache lifecycle/IO measurements and actual playback/analysis demux removal remain required before declaring a migrated combination.

Initial admission is a finite 188-byte TS, one recognized H.264 video track, progressive single-slice pictures, static single SPS/PPS and a syntax-proven initial IDR. Scrambled/error/discontinuous/truncated transport, split PES clock headers, clock wraps/jumps, interlace, ambiguous presentation timestamps and changing parameter sets fail explicitly. HEVC, MPEG-2/VVC, 192/204-byte transport, private stream configurations, live and dynamic tracks are outside this stage. A container key is only a candidate: payload syntax must prove IDR before using it as a closed anchor. General TS inventory and all other combinations must be handled in later routing/matrix work before removing an entire TS demuxer.

## Index and clocks

`js-ts-packets` schema 2 / `mediabunny-1.55.7-ts-packets-v2` binds source version, byte size, selected PID, configuration and stable decode ordinal. Mediabunny sequenceNumber is an opaque locator, never a direct compressed-byte range. Payload lookup accepts a timestamp candidate only after exact locator, length and timestamp checks. Every packet is checked for one picture and static parameter sets during index construction. Raw clocks are associated only when the locator is proven to begin that PES. Additional AUs have derived presentation time and unknown raw clocks; unproven original PTS disables precise playback identity and exact analysis. Missing DTS stays null, including 138 PES in the pinned 600-picture fixture; it is not replaced by PTS.

Decoded microseconds round the packet timestamp; original integer ticks remain separate. Packet WASM receives AV_NOPTS_VALUE for missing DTS, and analysis uses the known-clock bitmask. The exact picture/cache stream key includes selected PID and JS demux build, so old FFmpeg AU/cache identities cannot silently alias new ones. Cached documents validate version/build/stream/config/ordinal/clock shape and advertised complete packet count. These fields alone do not prove completeness. Only a still-live immutable complete JS enumeration can verify reuse; serialized records must match every verified record. Unknown or modified documents rebuild with JS even if their count/complete claims are self-consistent. The decoder-index conversion also rejects unverified metadata. Reused payloads also verify actual PES clocks and static in-band parameter sets. An independently owned analysis input in the same runtime can inspect a verified cached index without media reads or a WASM instance; its first payload miss initializes and verifies its own Input.

## Evidence and limits

`node-js-ts-packets` registers real-media Node checks: 600 stable records, warm reuse, wrong-build/source/ordinal/clock rejection, rear seeks, 600 actual packet-WASM outputs to EOF, full-precision visible plane comparisons against an independent container decoder, separate analysis identity and frozen H.264 block answers. Analysis deliberately traps the overlapping `_vpd_open` entry. Unknown DTS remains null in results. Raw buffer padding is excluded from pixel comparison, following the existing visible-plane oracle.

The raw-clock supplement scans transport headers and Mediabunny metadata traversal also reads payload. `bytesRead` counts adapter-returned bytes; it is not a zero-IO or physical-read measurement. `packetsRead` counts observed public packets and does not claim to count internal seek advancement. Cold initialization currently scans the complete finite source. Live immutable sealed objects retain weak identity authority independently of the bounded clone lookup. An analysis input seals and independently retains a proven clone before lazy payload IO, so releasing the playback original or evicting clone-lookup entries does not invalidate that analysis snapshot. The clone lookup holds at most 32 weak references and grants no authority to a document’s own checksum. Persisted documents after runtime restart or across independent Worker runtimes rebuild until a trusted source-owned snapshot boundary is established; reusable serialized metadata alone is not enough to issue exact answers. Actual Blob/Range IO, memory and first-frame/seek/cancel comparison, sparse-cache behavior, further corruption/configuration negatives and Chromium/WebKit native decoding remain outstanding. This stage makes no claim that JS is faster or that the product has stopped using the existing FFmpeg container path.

Admission checks pre-aborted signals before constructing the container runtime, including warm analysis, and closes the owned reader on failure. Raw PES-clock entries have the same 250,000-record bound enforced before insertion; failed scans clear clock metadata and close their source. The real/virtual negative tests cover dropped middle/tail records, renumbered and fake-complete caches, pre-aborted warm metadata, and 300,000 hostile PES headers without scanning the whole tail.
