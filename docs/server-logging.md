# 服务端日志留档

浏览器诊断仍只写本地 IndexedDB，由用户在日志面板主动上传。服务端运行日志和上传报告拥有独立目录、配额与保留规则。

## 默认策略

| 类型 | 位置 | 策略 |
| --- | --- | --- |
| 运行日志 | `dataDir/runtime-logs/` | 单段 10 MiB 或 UTC 跨天切段；封口 gzip；保留 60 天、合计最多 256 MiB |
| 上传报告 | `logsDir`（便携包默认 `data/logs/`） | 合计最多 512 MiB、1000 份；默认保留到手动删除，满额拒绝新上传 |
| 请求记录 | 运行日志中的 `http-request` 事件 | 按运行日志的时间、容量策略保留；默认每页 40 条，可选 20/40/100 条，支持页码跳转，重启后可查询；管理 GET 不进入列表 |

运行段按文件名中的创建时间淘汰，读取和下载不延长寿命。所有受管理 JSONL、gzip 和压缩临时文件都参与配额核算；压缩前为输出预留原段大小的 101% 加 16 KiB，不足时先淘汰旧段。当前写入段和正在压缩的源段受保护。单段上限也约束未压缩数据，总量按实际文件字节计算，不包括小型 SQLite 排他锁的文件系统开销。另有 1024 段的文件数量保护。

切段、压缩、配额回收由同一异步写入队列顺序完成，不阻塞 HTTP 路由等待压缩。队列最多 1 MiB，单条记录最多 16 KiB；超长记录保留有限预览，队列满或磁盘写失败会计数丢弃，恢复后写入 `log-records-dropped`。管理页显示磁盘错误、丢弃条数和当前占用。文件写失败只在失败阶段首次输出 stderr，防止递归记录。

关闭服务先停止请求和后台工作，再排空日志、同步并关闭当前段、等待压缩结束。gzip 写入独立临时文件，完整写入并同步后替换目标，再删除源段；失败保留 JSONL。重启删除残留压缩临时文件，重新压缩原段。崩溃前尚在内存中的日志可能丢失；运行日志不是事务审计账本。

启动时和每小时检查运行日志期限；写入超量时立即回收。启用报告过期后，在启动、每小时及报告操作时按文件最后修改时间清理。删除只触及匹配命名规则的普通文件，不跟随文件符号链接，不清理未知文件。日志目录通过独立 SQLite 排他锁保证单写入者；自定义共享 `logsDir` 不能被多个服务实例同时管理。

上传请求在读取正文前进入有界队列，提交串行检查份数与总字节，避免并发越过配额。报告先写临时文件并同步，再无覆盖发布；重启清理未发布临时文件。已满返回 HTTP 507 / `log-storage-full`，队列繁忙返回 429 / `log-storage-busy`。单次请求体仍限制为 10 MiB，服务端接收回执覆盖客户端同名字段。已超配额的历史目录保留已有报告，需下载并手动删除后才能继续接收。

## 配置

请求分页首次查询时从保留的 JSONL/gzip 分段建立临时磁盘索引；后续仅读取新增字节或新分段，并移除已淘汰分段的条目。索引在服务关闭时删除，可从日志重建；其临时磁盘占用与保留请求数成正比，不计入日志分段配额。查询与写入、压缩串行，避免读取半个写入或已释放的文件。概览旧接口仍保留最多 200 条内存兼容快照；管理页使用分页接口，旧页不自动轮询，刷新按钮主动重新查询当前页。

`voidplayer.config.json` 支持部分覆盖，修改后重启生效：

```json
{
  "logging": {
    "runtime": { "segmentBytes": 10485760, "maxBytes": 268435456, "days": 60 },
    "reports": { "maxBytes": 536870912, "maxFiles": 1000, "days": 0 }
  }
}
```

`reports.days: 0` 表示仅手动删除，设为正整数才自动过期。不要把客户端 7 天保留期限套用到用户上传的问题材料。`--no-logs` 仅禁用上传，不关闭服务端运行日志。

运行单段范围 64 KiB–128 MiB，总量至少为单段的三倍且不超过 16 GiB，保留 1–365 天。报告总量 1 KiB–64 GiB、1–100000 份，过期范围 0–3650 天。上传目录中的未知文件不在托管配额内；文件系统可用空间仍可能因其他数据不足。

## 记录内容与迁移

访问日志使用 `http-request` 事件，保留 requestId、actorId、实际 TCP peer、方法、无查询字符串的路径、状态、完成状态与耗时。异常记录统一携带有限长度的错误名、消息、堆栈和 cause；HTTP 入口额外带 requestId 关联请求。后台服务停止记录原始异常。请求正文、Cookie 和 Authorization 不进入访问记录。错误消息可能包含服务端路径，仅应向受信任的内网用户开放管理页。

普通前台运行继续镜像 JSON 到终端。若外部脚本另行重定向到文件，该外部文件仍由脚本拥有，应避免再次无界留档。

新安装的 macOS 用户服务通过 `scripts/service-runner.mjs` 捕获 Vite、Worker stderr 和启动失败等额外输出，独立保存在 `.run/service-logs/dev/` 或 `production/`，每段 1 MiB、总量 16 MiB、保留 60 天；子进程的常规服务记录直接进入 `dataDir/runtime-logs/`，避免重复镜像。旧服务需 `npm run service -- stop` 后重新 `install`；不自动停止正在运行的实例。旧 `.run/dev.log`、`.run/dev.error.log` 和手动创建的 `console.log` 不迁移、不自动删除。

## 回归与成本

`test/unit/server-logging.test.ts` 登记为 `node-server-logging`：用临时文件、真实 gzip 和排他锁验证大小/UTC 切段、按时间回收、压缩替换失败与重启恢复、慢 IO 队列上限、ENOSPC 恢复、并发报告配额和显式过期。采用小配额，数据量约数 MiB，不依赖媒体/core/浏览器。

扩充既有 `test/unit/admin.test.ts` 覆盖 HTTP 并发 201/507、保留历史报告及 500 堆栈/requestId/查询脱敏；扩充既有管理浏览器用例验证策略占用可见，复用原有亮暗和响应式检查，不新增浏览器矩阵。故障注入要求源段在失败后仍可读取，重启后内容逐条一致，独立预期来自文件实际解压与 HTTP 回执。

## 请求资源上下文

请求历史保留路径及白名单查询字段，媒体请求额外记录 `media.id/rootId/root/path/version/requestedVersion` 和合法单段 `range`。管理页直接显示所属库、相对路径和版本；运行日志回读保留相同字段。查询值按字段截断，不记录任意 URL 参数、cookie、Authorization、请求体或页面桥凭据。媒体上下文在分派请求前捕获，避免写入过程中位置改变或删除导致日志丢失目标。
