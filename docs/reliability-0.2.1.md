# v0.2.0 review 核对与 v0.2.1 验证

核对基线：本地 main 为 ab6e124，已包含 b1b7b3e 后的发布 schema 校验修复。2026-09-20 查询时 v0.2.0 构建成功，但 Release 仍是草稿；标签、构建完成和公开下载是三个不同状态。

## 核对结论

1. **成立**：恢复工作区未登记 opener，且恢复与色彩切换直接等待 opener。现在三个入口通过 openCandidate 登记重开函数、传递 AbortSignal、可取消等待并释放迟到源；恢复索引等待也可中止。失败恢复保留原工作区。
2. **成立**：Promise 链和 OffscreenCanvas 并未把原来的 CPU 转换迁出主线程，且产生了全尺寸 RGBA/scratch canvas。现在仅原生 sample 直接绘制小画布；CPU 像素复制一份有界缓冲后转移至独立 Worker，使用目标尺寸采样和共同 YUV 色彩规则。同步复制仍存在，需计入开销。
3. **成立**：旧任务 settle 会清除新任务的全局占用，500ms 只是队首检查。现在占用带独立 token，释放幂等，接受时启动期限；任务完成只能释放自身占用。任务总量有界，上传不再是完整帧串行链的一部分。期限依赖浏览器事件循环调度，不承诺主线程被其他代码阻塞时仍准时执行。
4. **成立**：既有测试丰富但手写清单漏掉新特性，恒零计数不能证明无额外读视频。发布工作流及 PR 全量自动发现测试并准备样片、FLV、FATE 和 pinned core；新增必要浏览器门禁。保留身份专项检查和非阻塞性能报告，不把性能报告等同于发布性能保证。
5. **风险成立，影响已局部实测，隔离延后**：索引上传解析、派生构造、重序列化及 SQLite 写入仍同步执行；本版不改变服务端存储架构。下一轮应隔离大索引 CPU 工作，并同时覆盖读取缓存和便携 Node/Bun 生命周期。

## 本机测量

命令：node scripts/bench-index-contention.mjs。Node 24.15.0、macOS，本地独立客户端/服务器进程；50 万包、约 18.00 MiB 合法索引，并发连续 64 KiB Range 读取。样本不代表所有机器、冷盘或所有长视频。

| 观测 | 结果 |
| --- | ---: |
| 无上传 Range p95 / max | 2.32 / 9.66 ms |
| 上传期间 Range p95 / max | 4.33 / 126.92 ms |
| 索引上传总耗时 | 226.45 ms |
| 服务端事件循环最大延迟 | 132.64 ms |
| 服务端进程峰值 RSS | 539.88 MiB |

尾部延迟与内存压力值得后续隔离，但不能据此推断真实播放器已经卡顿多少。脚本可以通过 INDEX_PACKETS 扩大数据量，不是发布耗时门禁。

check-thumbnail-worker.mjs 在 Chromium/WebKit 各执行三次 4K RGBA、三次 4K YUV，验证原缓冲未转移、无媒体请求、输出旋转/颜色、字节缓存持久化与资源释放。RGBA 同步复制约 2–3ms，YUV 约 0–1.4ms；Chromium PerformanceObserver 未记录长任务。WebKit 不提供该 longtask 观测能力，空数组不能作为长任务不存在的证明。完整帧持有峰值为一份 33,177,600 字节 RGBA，非进程峰值内存。

播放基准使用 scripts/bench-playback.mjs webkit --headless，四组场景各三次，覆盖 4K HEVC、VVC WASM、VVC+HEVC 和 MPEG-2 TS+H.264；12 次通过既有阈值。这是本机阈值检查，不是跨平台无回退证明。

## 确定性与连续操作回归

- 恢复后切换解码参数，保持媒体 ID、偏移、时间和标注。
- 挂住恢复/色彩重开，取消后在旧源仍未返回时完成下一操作；迟到源仅释放一次。
- 模拟 A 释放后等待、B 占用、A 完成、C 申请；验证 C 被拒绝。模拟时钟推进到期限，B 立即释放，重复清理不影响新占用。
- 两种浏览器的工作区导入→设置重开、缩略图共享与缓存读取；真实请求观察验证已缓存封面不读取视频。
