# Roadmap

2026-09-07 确定。实施顺序：**3 部署基础 → 1 媒体库 → 2 管理后台**，随后完成首个正式 release 的验收。本文记录计划，未勾选项尚未完成。

## 已确定的交付方向

- 用 Bun `build --compile` 将服务端及运行时打成独立可执行文件，最终用户无需安装 Node、Bun 或 npm 依赖。
- 发布包包含 `voidplayer` 可执行文件（Windows 为 `.exe`）、构建后的网页/WASM 资源、配置示例和许可证。首版保留资源目录，不要求所有资源塞进单个二进制。
- 配置、索引数据库、日志及后续上传内容放在独立可写数据目录；程序升级不覆盖用户数据。
- 本地与远端运行同一套服务。开发、前端构建和现有测试可以继续使用 Node/npm，发布运行时采用 Bun。
- 为支持的操作系统和架构分别构建、验证产物；具体首发平台矩阵在部署阶段确定，不把交叉编译成功当作目标平台验收通过。

## 阶段 1：媒体库重做

目标：可靠管理多个物理或网络存储根目录下的大量嵌套视频文件，播放不受全库扫描阻塞。

- [x] 明确稳定的根目录/媒体 ID、内容版本、目录层级及旧工作区引用的兼容或迁移方式。首次配置写入稳定根 ID，媒体 URL 固定元数据版本；旧工作区按已存大小/修改时间核对后迁移，别名与最近记录保留兼容。旧记录不含版本时无法追溯历史字节，限制已记录。
- [x] 使用持久化索引，数据库存放在服务端本地数据目录；重启后可查询上次结果。SQLite schema 1 已在三平台独立产物上验证，包括停机备份后媒体离线时恢复缓存。
- [x] 后台扫描与媒体读取分离，提供扫描进度、错误、取消与恢复能力。状态和控制 API 已实现；恢复从根目录重新校准已存索引。扫描停滞时四路 HTTP Range 不等待扫描，崩溃后进程锁释放。
- [x] 目录浏览、面包屑、分页和当前目录/全库搜索，替代一次返回并渲染整个媒体库。UI 与 Agent 均使用有界分页，集合变化以 revision 明确失效并返回第一页；最近记录独立查询，不依赖当前页。WebKit/Chromium 交互与亮暗外观已验证。
- [x] 处理深层目录、大量文件、文件写入中/替换/删除和权限不足，不再静默漏项。5100 文件、12 层目录和各状态已有后端回归；UI 展示待写入/离线/扫描错误数量，版本改变阻止旧工作区还原。真实网络挂载另行验收。
- [ ] 网络存储首版使用操作系统已挂载的路径；离线时保留索引并标记状态，重连后校准。
- [x] 增量更新、手动刷新与周期校准配合。目录提示合并为局部扫描，监听最多 512 个句柄，超限/不可用退回周期校准；初次注册补查、目录身份更换、取消排队任务和写入稳定复查均已验证。文件监听仅作提示，不作为网络存储完整性的唯一依据。
- [ ] 验证扫描期间多轨 Range 请求、断线恢复、服务重启及现有工作区导入。

详细候选模型见 [媒体库演进方案](media-library-evolution.md)。收藏、服务器评审集合等扩展能力不自动成为本阶段必做项。

## 阶段 2：服务端管理后台

目标：围绕实际的数据和任务提供管理能力，与播放器共用服务端接口。

- [x] 独立 `/admin` 入口；播放器连接状态入口在新标签页打开服务端管理界面。WebKit/Chromium 已验证独立入口、主题同步和响应式布局。
- [x] 管理身份、访问权限和写操作边界。本机要求回环连接与 Host；远端沿用可信网关身份及显式管理员名单，写操作校验同源与动作头。
- [x] 管理媒体根目录与扫描任务，查看不可读目录、离线存储和索引状态。根目录保留稳定 ID，配置带版本校验并原子写回；外部修改或启动参数覆盖时暂停后台保存，更新后立即校准索引。
- [x] 展示服务版本、运行状态、连接、资源使用及诊断日志。日志提供有界分页、JSON 预览、下载和按版本删除，上传归属由服务端记录；本次运行请求记录保留最近 200 条。
- [x] 分别测量客户端到服务端吞吐、存储读取能力和并发服务能力，明确测试条件与耗时；主动测速由用户触发。提供内存下载、上传、单路存储及四路媒体读取，显示浏览器/服务器计时来源、数据量和缓存影响；任务受时长、数据量、并发数限制并支持取消。
- [x] 定义端侧上传/编辑对象的持久化、归属、版本与冲突处理，再提供对应的检视和管理页面。首版为主动上传的诊断日志与主动保存的工作区；工作区独立 SQLite 持久化，归属由服务器生成，版本匹配后才能更新/删除，冲突保留本地会话并可另存副本。播放器和管理页均已接入。

上传/编辑范围为诊断日志和工作区，不包含通用文件管理器、视频上传或实时协作。工作区当前版本可编辑，版本号用于冲突检测，不承诺完整版本历史；客户端内容仍只在用户主动上传或保存时发送。

## 当前状态

部署基础、媒体库和管理后台已落地，当前推进正式发布验收。发布脚本使用独立可执行文件加资源目录。macOS ARM64 预览产物通过空 PATH、与源码无关的工作目录、归档校验、初始化、并发 Range、中断、网关身份和更换程序目录保留配置/日志测试；独立服务上的四组 WebKit 播放基准通过。

正式打包入口已切换为 GitHub Actions：主分支代码推送、版本标签或手动触发，固定 core 构建仓库、FFmpeg、dav1d 修订和工具链，从源码准备同一份解码器，再由 Linux x64、Windows x64、macOS ARM64 原生 runner 打包并测试。分支预览产物与校验和保留 30 天；版本标签经三平台验证和汇总后创建 Release 草稿，公开发布仍需完成正式验收。详见 [发布与校验](../deploy/README.md#发布与校验)。[三平台独立产物、备份恢复及部署验证已通过](https://github.com/Nakiha/VoidPlayer-Web/actions/runs/34053905776)，对应应用修订 `b97915d`。Linux 额外验证随包 Docker/Compose/Caddy 的非 root、只读运行、无 Node/Bun、可信 TLS、认证边界、并发 Range 与重启后保留 CA；Windows 已验证真实独立控制台 Ctrl+C 正常退出。这是部署基础阶段的历史验收；后续媒体库/管理后台记录见下方。签名与公证尚未提供，真实网络存储仍待验收，不标记整个 roadmap 完成。
