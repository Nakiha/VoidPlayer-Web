# 帧契约与回归验收 Roadmap

2026-09-07 启动。基线：PR #2 合并提交 `6b95088`；开发分支 `codex/frame-contract-refactor`。
目标是让首帧、顺序播放、定位和关闭重开具有同一套可验证的输出约定。
本地/HTTP 可以使用不同读取实现；不能因此改变帧内容、显示顺序或定位语义。

## 1. 固定反例和验收标准

- [ ] 固定 FATE 参考逐帧 PTS、尺寸及像素指纹，注明生成工具；测试时不随本机 ffprobe 改写标准。
- [ ] Node 与 Chromium/WebKit 共用结果校验，检查首帧、顺序输出、往返定位和重开。
- [ ] 区分必须通过、明确的能力拒绝、已知缺陷；未预期的失败使检查失败，已修复项提升为门禁。
- [ ] 用错误尺寸、少帧和错误定位结果验证校验器确实能捕获静默错误。

## 2. 完整输出帧

- [ ] 在 FFmpeg-Build 仓库完善逐帧 ABI：有效像素尺寸、长度、stride、时间戳、源像素格式/色彩和输出描述版本。
- [ ] core → Worker → DecodedFrame → presenter 共用帧描述，边界校验和资源释放明确。
- [ ] 原生帧区分像素几何、显示几何与色彩，不用打开时的快照重标后续帧。
- [ ] 普通 WASM 两种 core 的多配置 MOV 首帧、完整播放及跨段往返定位通过。
- [ ] 更新固定 core 修订前，先提交并推送上游源码；验证产物来源和必需接口。

## 3. 配置切换与显示时间线

- [ ] 区分包索引、解码顺序、显示时间线和定位预滚，输出帧作为显示事实。
- [ ] MP4/FLV 按配置段解码，段末保留延迟帧，跨段 seek 恢复正确配置。
- [ ] 处理 B 帧重排和结尾 drain，不跳过不匹配帧冒充命中。
- [ ] 定位采用同一规则：返回目标时刻之前最近的显示帧；首尾夹取，逐帧不重复不漏帧。
- [ ] 多配置 MOV、无重排约束 B 帧、隔行裁剪反例在适用后端及本地/HTTP、关闭重开中通过。

## 4. 状态变更与诊断

- [ ] 用统一元数据变更入口/版本替代 UI 中分散的字段签名，UI、Agent 和本地日志消费相同状态。
- [ ] 当前显示尺寸/色彩只随实际展示帧更新，后台索引可独立更新时长和索引状态。
- [ ] 操作、目标帧、实际送包、配置与实际输出可关联；错误保留原阶段，日志有界且只留本地。
- [ ] 验证后台索引完成、动态尺寸、失败/取消及资源回收；现有 UI 和 Agent 行为一致。
