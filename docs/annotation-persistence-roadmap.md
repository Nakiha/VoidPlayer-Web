# 标注持久化与协作

基线：PR #3 已合入 main（d72fa84）。本轮分支：codex/annotation-persistence。

## 产品约定

共享评审空间和标注；播放位置、轨道布局、缩放保持客户端独立。默认空间可直接使用，也可另建空间隔离评审。全员可信，身份只记录作者和修改者。

标注绑定媒体版本与片内帧位置；库文件被替换后不得套用旧标注。本地文件不会被上传，保留本机草稿和可导出的工作区。工作区导入作为快照恢复，不无条件覆盖共享标注。

## 四批交付

- [x] 1. 独立存储：评审空间、逐条标注版本、幂等操作、软删除、迁移/导入边界。
- [x] 2. 自动保存：IndexedDB 待提交队列、断网重试、增量拉取、冲突草稿、准确保存状态。
- [x] 3. 预览：独立图片、限量延迟生成与加载、图片失败不阻塞标注、播放性能对比。
- [x] 4. 管理及验收：搜索/预览/导出/删除/恢复/缓存清理，双窗口与重启回归。

## 必须验证

- 两人编辑不同标注互不覆盖；同一版本的编辑与删除只有一个成功。
- 已删除记录不被旧编辑、旧快照或断网重试复活。
- 请求已落库但响应丢失，重试不重复创建；使用相同操作编号但不同内容必须拒绝。
- 刷新、离线和服务重启不丢失已确认保存的数据；本机失败不能显示“已保存”。
- 用户/空间切换不会将旧请求、草稿或缩略图提交到新空间。
- 同路径新版本不继承旧标注；移除库目录不删除用户数据。
- 后端管理修改使用与播放器相同的版本校验；删除与缓存清理分开。
- 标注同步不 seek、不重新载入媒体、不改变播放位置和布局。
- 缩略图创建/上传失败不阻塞文字和矢量保存；播放时不启动额外画面捕获。
- 亮暗/窄窗口实际截图；构建、单元、浏览器、工作区兼容和播放基准。

## 后续边界

自动时间戳索引和雪碧图后续实现。可重建产物按“媒体版本、产物类型、生成规则版本”标识；与用户标注分开管理。后台计算限并发、可取消，不在媒体 Range 请求中执行。当前不引入 WebSocket、协同逐点画笔或通用任务平台。

## 统一缓存管理

后台侧栏统一为「缓存」，纳入 FLV 帧索引与标注预览。两类各有 256 MiB 的内容上限；列表按需加载，每次 50 条，可搜索、清理单项或整类。标注页不再放置预览清理操作。

顶部显示内容总量和所在磁盘的总量、已用、进程可用空间。存储位置展开显示数据库路径、数据库文件与 WAL 大小。帧索引位于 library.sqlite 的 frame_indexes；预览位于 annotations.sqlite 的 annotation_previews。两者均与业务数据共用数据库，因此内容字节数与数据库文件大小分别报告，清理只释放可复用页，不在播放服务里执行 VACUUM，不承诺立即缩小文件。

工作区、标注正文、媒体身份、日志和证书不属于可清理缓存。清理使用类型白名单及逐条版本校验；缓存代次拒绝清理前已发出的上传。预览可在后续编辑对应画面时重新生成。

## 当前边界

缩略图是逐版本的 320 像素宽 JPEG 预览，与文字/矢量独立存储；首轮仍包含绘图合成，不提供雪碧图。单张 128 KiB 上限，暂停时生成/上传，失败不影响正文保存。

共享恢复要求同一媒体版本的库引用。本地文件不上传；重新选择文件仍需通过工作区快照和重新关联恢复，不用同名/大小/时间戳猜测其身份。本机草稿可导出为现有工作区格式，导入保持快照，另存到共享空间产生新标注 ID。

本轮采用前台每 3 秒增量同步与逐条乐观版本检查，没有引入 WebSocket 或多人逐点画笔同步。服务端标注和幂等记录属于用户数据，不能从「缓存」页清理。
