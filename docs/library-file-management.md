# 媒体库文件管理

后台媒体库列表和分栏共用单列选中状态：普通点击单选，文件夹同时打开；Shift 选择同列连续范围，Command（macOS）或 Ctrl（Windows/Linux）切换独立项目。多选不触发目录跳转。在另一列选择时清除旧列的选中，祖先路径只保留中性背景。方向键移动选中，Enter/右方向键打开文件夹，Command/Ctrl+A 选择当前列已载入的项目。

鼠标拖拽移动选中项，预览最多展示五行，数量徽标显示实际数量。目标可以是文件夹、库挂载行、路径按钮或目录空白区域；边缘自动滚动。Escape 或无效位置松开取消。触屏保留既有长按菜单；本轮不把触屏滚动解释为拖拽。文件单击只选中，右键仍可显式在播放器打开；界面不提供删除或改名。

## 服务接口

`POST /api/library/files` 沿用管理写入的同源 Origin 与 `X-VoidPlayer-Action: library-files`，要求 `Content-Type: application/json`，正文上限 64 KiB。该校验与既有管理接口一致，不构成用户认证。

```json
{"operation":"move","sources":[{"rootId":"video","path":"take.mp4","kind":"file","version":"0123456789abcdef01234567"}],"target":{"rootId":"video","directory":"review"}}
```

改名使用 `{"operation":"rename","source":REF,"name":"new.mp4"}`；删除使用 `{"operation":"delete","sources":[REF]}`。REF 为 `{rootId,path,kind,version?}`，kind 为 file/directory；文件必须固定浏览结果中的 24 位 version，目录在受理时以实际目录身份建立本次执行见证。路径均为挂载根目录下的相对路径，不能操作挂载根目录或包含其他挂载的父目录。

每批最多 100 项。受理前检查全部源、目标冲突、重复/父子选择、目录自包含和符号链接路径；不覆盖同名文件、不合并目录。初始校验失败无写入。文件移动使用独占目标链接或跨卷独占复制，再核对源 inode/设备/尺寸/mtime 后移除源。复制后的源核对或移除失败会保留两端；不能把这种响应视为成功或自动重试。文件夹目前只支持同文件系统改名/移动；跨卷文件夹在预检阶段拒绝，不递归复制再删除。

响应形状为 `{results:[{source,destination?,ok,error?}],indexRefreshed}`。多项执行不是文件系统事务，执行中故障可有部分成功，必须逐项检查 results；应用内文件写入串行，配置变更与另一批写入会收到 409。服务关闭等待已受理的真实文件操作退出。外部程序并不受应用锁约束，源在每项执行前再次核对；这不是对恶意外部文件系统竞争的隔离保证。

操作后重新扫描受影响的父目录，未完成索引刷新时显式返回 indexRefreshed=false。路径改变会产生新的媒体库 ID/版本，原引用按既有失效规则处理；不重新关联历史评审、标注或评分，也不自动打开视频、建帧索引或解码。失去 HTTP 响应时结果未知，客户端只重新观察目录，不重放写入。UI 继续显示现有媒体库支持的媒体文件和文件夹，移动整个文件夹会保留其非媒体内容。
