# CAMBI 筛查观察与旧代理指标迁移评估

本次补齐 #116 的筛查观察和 #121 的本机资源记录。功能候选为
`542ef11e588d88e85d4d9b7a1625cf89fbc655f5`，测量时工作区干净。
这是有明确构造的素材观察；没有主观标注，不给出通用准确率或质量合格线。
功能契约见 [CAMBI](native-cambi.md)，准入规则见[评分资源管理](quality-resources.md)。

## 可复现方式

```sh
node scripts/tools/diagnostics/evaluate-cambi.mjs --rounds=3
```

需要同步固定播放/分析 core、安装项目依赖以及本机 ffmpeg/ffprobe。
工具生成输入，经真实 HTTP 持久任务和生产 Worker 执行，并逐帧、逐尺度核对
独立官方对照。实际评分仍由既有分析 WASM 完成。完整输入 hash、算法参数、
core/组件 hash、每次计时及资源观察在[原始记录](validation/cambi-screening/macos-arm64.json)。
官方输入的许可随 `test/helpers/native-cambi-official-NOTICE.txt` 保留。
这是 manifest 中无默认套件的显式 diagnostic；不加入云端 CI 性能测试。

固定 Netflix/vmaf 修订 `17a67b238ce0539bdeafdc95961abac64fa16ea8`，
no-reference、BT.1886、window63、topk0.6、tvi0.019、maxLogContrast2、
单线程 scalar，保持原尺寸、limited BT.709 SDR 和实际 8/10-bit 输入。
CAMBI 逐帧计算，没有时间跟踪；分数更高表示更多色带线索。算法定义见
[固定版本上游文档](https://github.com/Netflix/vmaf/blob/17a67b238ce0539bdeafdc95961abac64fa16ea8/resource/doc/cambi.md)。

每组 4 帧，8/10-bit 各一次独立输入，三个冷 Worker 作业，共 36 个作业。
OS 文件缓存可能已热。合成图为 640×352；自然输入使用固定官方处理帧重复
四次，10-bit 版本由 8-bit 码值左移得到，不恢复原始精度。

## 数值与混淆观察

三个重复的逐帧分数、池化结果和全部五尺度热图均与官方对照一致。
下表展示池化均值；原始记录保存更完整精度。为观察粗阶梯筛查，工具显式使用
示例阈值 10。此阈值没有校准，不是产品默认值或建议值。

| 输入 | 8-bit | 10-bit | 示例阈值下的观察 |
| --- | ---: | ---: | --- |
| 阶梯渐变 `100+floor(x/24)` | 19.310590 | 19.317805 | 命中人工加入的阶梯 |
| 平滑斜坡 `80+140*x/width`，按输入位深量化 | 11.802179 | 0 | 8-bit 对“额外粗阶梯”策略误报；自身量化平台不等于无色带基准 |
| 周期细纹理，随帧变化 | 0 | 0 | 此构造未触发 |
| 阶梯渐变叠加确定性 `[-7,7]` 噪声 | 0 | 0 | 漏掉注入的阶梯；噪声可能掩蔽可见性，不能据此称作人眼可见缺陷漏检 |
| 恒定亮度/色度平面 | 0 | 0 | 此构造未触发 |
| 自然处理帧，未标注 | 0.210759 | 1.093501 | 仅作稳定性观察，不给正确/错误判断 |

这些结果支持继续把 CAMBI 用作可复核候选：低分不保证无缺陷，高分不自动
判定画质不合格。纹理、颗粒和位深会影响解释，不能把 8-bit 与 10-bit
阈值直接视为等价。候选保留原帧、五尺度和真实覆盖信息，由使用者复核。
本组没有覆盖真实相机运动、切场、闪烁、HDR 或有主观标注的代表性节目库；
不把小样本结果外推成总体误报率/漏报率。

## 五类旧代理指标的迁移决定

核对本体 `quality-demo-v5`，固定源码为
[`881eb5c` 的 quality_metrics.cpp](https://github.com/Nakiha/VoidPlayer/blob/881eb5ccd706c33aa1ff35ab3a67ac3a226ccfba/native/analysis/quality/quality_metrics.cpp)。
旧输出为约 64×64 分块、0–1 代理值，与 CAMBI 分数和五尺度空间证据不同。

| 指标 | 原实现及主要混淆 | 本次决定与后续准入条件 |
| --- | --- | --- |
| blockiness | 固定 8/16 周期边界统计，周期纹理也可能触发 | 暂不移植；需独立编码块效应/纹理对照及 8/10-bit 校准 |
| banding | 自研局部代理，不能继承其阈值及瓦片语义 | 使用固定官方 CAMBI；保留以上误报/漏检观察及原生多尺度证据 |
| blur | 原图与再模糊图的方向差分/梯度，取方向最大值；受内容细节影响 | 保留实验评估，需独立模糊强度和自然低细节负样本 |
| noise | 16 像素块、梯度筛选及高通估计；纹理和胶片颗粒混淆 | 保留实验评估，需区分噪声、纹理和创作颗粒，不将颗粒默认判为缺陷 |
| flicker | 三帧均值/分块曲率，已有场景差阈值 0.20，未做运动补偿 | 保留实验评估；需运动、切场及曝光变化的时序对照，不用 CAMBI 分差冒充闪烁检测 |

本次仅纳入有独立官方数值及空间证据的 banding；其他四项没有新增占位
执行器或产品入口。后续只有取得独立输入/数值/混淆证据后才进入产品能力。

## 本机资源及播放观察

2026-10-30，Apple M5、ARM64、10 逻辑 CPU、32 GiB、Node 24.15.0。
功能套件完成后顺序执行此轮观察，未同时运行其他项目重型测试。
36 个作业的持久排队时间为 0–1 ms，执行时间 207–347 ms；每个作业只处理
4 帧，不能据此推算长片吞吐。评分 WASM heap 为 64 MiB。
10 ms 抽样的整个服务/测试进程 RSS 峰值范围约 324–482 MiB，包含 Workers、
缓存及夹具开销，既不是单任务精确峰值，也不是准入内存硬上限。

只读媒体库顺序探测：各作业运行前的样本 p95 为 0.60–2.51 ms，运行中为
0.62–3.90 ms。每作业最多 128 次，无洪泛和百分位门槛；这不认证高负载 HTTP。
默认并发仍为 1，调高并发必须同时满足内存、累计读取和内部线程预留。

此后单独运行既有 WebKit 离屏播放基准，四场景各三次，共 12/12 通过原有
速度、帧差、间隔及暂停断言，未修改门槛。场景为 HEVC 4K、VVC、VVC+HEVC 4K、
MPEG-2 TS+H.264；[精简结果](validation/cambi-screening/playback-macos-arm64.json)
记录每次实测。双浏览器 CAMBI 功能回归另验证评分期间原播放器继续播放；
这里的播放基准独立运行，不冒充并发评分下的吞吐或物理屏幕扫描认证。
