# 媒体库索引与演进

实施顺序以 [Roadmap](roadmap.md) 为准。当前已实现持久化索引、后台扫描、播放器目录导航和分页，以及带版本的工作区/最近片源引用。增量目录扫描与有界监听已接入；管理后台与真实网络存储验收仍待完成。

## 配置与数据

`mediaRoots` 接受旧的路径字符串，也支持带稳定 ID 的对象。新部署建议使用对象：

```json
{
  "mediaRoots": [
    { "id": "archive", "name": "实验归档", "path": "/mnt/archive" },
    { "id": "local", "name": "本机素材", "path": "/srv/media" }
  ],
  "indexTtlMs": 30000,
  "indexWatch": true
}
```

相对路径按配置文件所在目录解析，ID 和路径不能重复。SMB/NFS 等存储先由操作系统挂载，再将挂载路径加入白名单。通过 `/admin` 保存根目录时即刻重新校准，保留稳定 ID 与已有读取；直接编辑配置文件仍需重启。其他服务配置暂不热加载。

独立程序使用 `--data-dir` / `VOIDPLAYER_DATA_DIR` / 系统用户数据目录，SQLite 数据库为 `library.sqlite`。源码运行可配置 `dataDir` 或传入 `--data-dir`，默认 `.run/data`。数据库必须放在服务器本地可写磁盘，不能放进只读程序目录或网络媒体盘。Docker 使用独立的 `app-data` 卷。

同一数据目录只允许一个服务写入，第二个进程启动时明确报错。独立 SQLite 锁事务在进程崩溃后由操作系统释放；重启将未结束的扫描标记为 `interrupted`，自动重新校准。

## 身份与内容版本

- 路径字符串沿用旧算法：媒体 ID 是根目录绝对路径与相对路径的 SHA-256 前 24 位。现有工作区 URL 保持可用。
- 对象根目录使用稳定 `id` 与相对路径生成媒体 ID；同一根 ID 更换挂载路径后，已有记录仍保留原 ID。
- 索引保存旧路径算法的别名。旧配置切换为对象后，重新扫描同一路径可继续解析旧 URL；如果同时迁移目录，应先在旧路径完成一次索引，再保留数据库、固定根 ID 修改路径。
- 文件重命名视为新相对路径，不推断为原媒体；删除的记录保留为 `missing`，用于避免把历史引用误认为从未存在。
- `version` 是大小、mtime、ctime、inode 的元数据指纹，不是文件全文哈希。API 可用 `/api/media/<id>?v=<version>` 固定版本；版本不符返回 409。文件描述符打开后再次校验指纹，防止校验和读取之间替换文件。

旧的无版本 URL 仍可读取当前已索引的文件，不能据此证明历史评审与当前字节一致。播放器的新载入、最近片源和工作区导出均固定版本。导入旧工作区先核对大小与修改时间，再迁移到当前版本；这不能证明历史字节相同，只有原始记录已有版本时才能核对该版本。内容或版本不匹配会提示重新选择，并保留当前工作区。

## 后台扫描

启动后立即扫描，默认每 30 秒校准一次，周期由 `indexTtlMs` 控制。同类扫描请求合并为一个任务；全库刷新不会被正在运行的局部扫描吞掉，会在其结束后校准。Range 请求只查已有记录并验证目标文件，从不触发或等待全库扫描。重启先提供已持久化的结果，同时后台刷新。

扫描采用逐目录异步遍历，没有 6 层或 5000 文件的索引上限。按媒体扩展名过滤，跳过隐藏项和符号链接。元数据每批最多 64 个文件写入数据库，事务不跨越文件 I/O 等待；扫描不提供全库原子快照。新写入和替换的文件先标记 `pending`，连续稳定至少一秒后才允许播放。

全库校准仅在整个根目录扫描成功时清理未再发现的条目；增量扫描仅清理成功检查的子树，不触及兄弟目录。目录权限不足、超时、断线或取消时保留旧记录，并记录 `partial` / `offline` / `cancelled`。根目录离线不阻止服务启动，`--init` / `--check` 仍严格检查媒体路径。文件操作有超时，取消不会等待完整遍历；操作系统底层正在进行的文件 I/O 本身不能被 Promise 取消。

监听仅注册扫描器已验证的目录，不递归跟随符号链接。默认最多 512 个系统监听句柄；350 毫秒合并同一批提示，祖先目录覆盖子目录，每个根最多保留 128 个待扫描子树，超出后合并为该根校准。写入中的媒体稳定复查也只扫描所在目录。扫描过程中收到的变化会排队，不丢弃为“已有任务”。

`indexWatch: false` 可以关闭监听，手动刷新和周期校准照常工作。系统不支持监听、句柄配额不足或 SMB/NFS 漏报时仍依赖周期校准；每次校准检查目录身份，只在目录替换或挂载重连时更换句柄；新注册后补查一次，覆盖注册初期的事件空隙。成功校准后释放已删除目录的句柄。索引状态提供监听数量、上限、受限标记及不可监听根 ID。监听不是完整性保证，也不是网络盘已在线的证明。

扫描状态包含目录数、媒体数、当前相对路径与错误数。保留最近 50 个完成任务；每次最多保存 1000 条错误详情，超过时标记详情截断。取消后可再次刷新，从根目录重新校准已有索引，不宣称从目录内的精确位置续传。

## 接口

- `GET /api/library/browse`：`root`、`directory`、`search`、`recursive=1`、`limit`（1–200）、`offset`；返回当前目录的媒体与子目录、扫描状态及下一页位置。递归搜索不返回目录行。
- `GET /api/library/scan`：任务状态、根目录状态和本次错误详情。响应不包含根目录绝对路径。
- `POST /api/library/scan?action=refresh|cancel`：返回 202，不等待扫描；要求同源 `Origin` 与 `X-VoidPlayer-Action: scan`，远端同时需要现有网关认证。
- `GET /api/media/<id>/metadata`：查询已存元数据，支持旧 ID 别名，最近片源因此不依赖当前目录页。
- 旧 `GET /api/library` 仅保留为兼容接口，最多 5000 项，超过返回 `truncated`。当前 UI 与 Agent 均改用分页接口，不再调用它。

分页响应携带 `revision`，后续页和轮询带回该值。文件或目录集合变化时返回 409，页面提示并回到第一页，避免静默跳项。无变化扫描不会使分页失效。每页最多 60 个媒体及 60 个子目录，当前目录与全库搜索在服务端执行；本地文件/最近记录在浏览器内过滤。
