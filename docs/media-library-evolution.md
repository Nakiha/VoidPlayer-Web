# 媒体库索引与演进

实施顺序以 [Roadmap](roadmap.md) 为准。当前已实现服务端持久化索引和后台扫描基础；播放器仍使用旧的扁平列表，目录导航、分页界面与工作区版本提示尚待接入。

## 配置与数据

`mediaRoots` 接受旧的路径字符串，也支持带稳定 ID 的对象。新部署建议使用对象：

```json
{
  "mediaRoots": [
    { "id": "archive", "name": "实验归档", "path": "/mnt/archive" },
    { "id": "local", "name": "本机素材", "path": "/srv/media" }
  ],
  "indexTtlMs": 30000
}
```

相对路径按配置文件所在目录解析，ID 和路径不能重复。SMB/NFS 等存储先由操作系统挂载，再将挂载路径加入白名单。修改配置后重启服务；暂不热加载。

独立程序使用 `--data-dir` / `VOIDPLAYER_DATA_DIR` / 系统用户数据目录，SQLite 数据库为 `library.sqlite`。源码运行可配置 `dataDir` 或传入 `--data-dir`，默认 `.run/data`。数据库必须放在服务器本地可写磁盘，不能放进只读程序目录或网络媒体盘。Docker 使用独立的 `app-data` 卷。

同一数据目录只允许一个服务写入，第二个进程启动时明确报错。独立 SQLite 锁事务在进程崩溃后由操作系统释放；重启将未结束的扫描标记为 `interrupted`，自动重新校准。

## 身份与内容版本

- 路径字符串沿用旧算法：媒体 ID 是根目录绝对路径与相对路径的 SHA-256 前 24 位。现有工作区 URL 保持可用。
- 对象根目录使用稳定 `id` 与相对路径生成媒体 ID；同一根 ID 更换挂载路径后，已有记录仍保留原 ID。
- 索引保存旧路径算法的别名。旧配置切换为对象后，重新扫描同一路径可继续解析旧 URL；如果同时迁移目录，应先在旧路径完成一次索引，再保留数据库、固定根 ID 修改路径。
- 文件重命名视为新相对路径，不推断为原媒体；删除的记录保留为 `missing`，用于避免把历史引用误认为从未存在。
- `version` 是大小、mtime、ctime、inode 的元数据指纹，不是文件全文哈希。API 可用 `/api/media/<id>?v=<version>` 固定版本；版本不符返回 409。文件描述符打开后再次校验指纹，防止校验和读取之间替换文件。

旧的无版本 URL 仍可读取当前已索引的文件，不能据此证明历史评审与当前字节一致。播放器、最近片源和工作区需要在下一步接入版本引用与明确的变更提示，不能自动将旧标注绑定到替换后的内容。

## 后台扫描

启动后立即扫描，默认每 30 秒校准一次，周期由 `indexTtlMs` 控制。扫描请求合并为一个任务；Range 请求只查已有记录并验证目标文件，从不触发或等待全库扫描。重启先提供已持久化的结果，同时后台刷新。

扫描采用逐目录异步遍历，没有 6 层或 5000 文件的索引上限。按媒体扩展名过滤，跳过隐藏项和符号链接。元数据逐步写入数据库；扫描不提供原子快照。新写入和替换的文件先标记 `pending`，连续稳定至少一秒后才允许播放。

仅整个根目录扫描成功时才清理未再发现的条目。目录权限不足、超时、断线或取消时保留旧记录，并记录 `partial` / `offline` / `cancelled`。根目录离线不阻止服务启动，`--init` / `--check` 仍严格检查媒体路径。文件操作有超时，取消不会等待完整遍历；操作系统底层正在进行的文件 I/O 本身不能被 Promise 取消。

扫描状态包含目录数、媒体数、当前相对路径与错误数。保留最近 50 个完成任务；每次最多保存 1000 条错误详情，超过时标记详情截断。取消后可再次刷新，从根目录重新校准已有索引，不宣称从目录内的精确位置续传。

## 接口

- `GET /api/library/browse`：`root`、`directory`、`search`、`recursive=1`、`limit`（1–200）、`offset`；返回当前目录的媒体与子目录、扫描状态及下一页位置。递归搜索不返回目录行。
- `GET /api/library/scan`：任务状态、根目录状态和本次错误详情。响应不包含根目录绝对路径。
- `POST /api/library/scan?action=refresh|cancel`：返回 202，不等待扫描；要求同源 `Origin` 与 `X-VoidPlayer-Action: scan`，远端同时需要现有网关认证。
- 旧 `GET /api/library` 保留扁平兼容接口，最多 5000 项，超过返回 `truncated`；过期列表会等待扫描。旧 UI 的限制仍存在，不能把它当成完整盘点结果。

当前分页使用稳定排序后的 offset；扫描中集合变化可能移动页边界。前端接入前需完善分页一致性、目录过滤与状态提示。

## 后续交付

1. 目录浏览、面包屑、分页与当前目录/全库搜索，沿用播放器斑马色和紧凑操作区。
2. 版本 URL、旧工作区/最近片源兼容、内容改变与离线状态的明确提示。
3. 去抖增量扫描和可选文件监听；网络存储仍以周期校准兜底。
4. 在真实本地和网络挂载上验证多轨播放、断线恢复与大型目录，不以临时测试目录代替真实验收。

评审集合、收藏和共享注释属于后续产品能力。端侧上传内容仍遵守用户显式操作与网关身份边界，媒体文件始终只读。
