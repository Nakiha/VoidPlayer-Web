# 实验视频媒体库：现状与建议

候选设计，尚未实施。媒体库重做已列入 [Roadmap](roadmap.md)，安排在部署基础之后、完整管理后台之前；具体范围以 Roadmap 为准。现状以 `server/library.ts` 和 `server/config.ts` 为准。

## 当前行为

- `server/config.ts` 读取 `voidplayer.config.json`（或 `--config` / `VOIDPLAYER_CONFIG`），`mediaRoots` 接受多个白名单目录；也可重复指定 `--folder`。配置文件里的相对路径相对配置文件解析。示例配置使用 `fixtures/video`。
- `server/runtime.ts` 启动前检查目录、建立内存索引。没有 fs.watch，也不会热加载配置。
- `server/library.ts` 递归扫描根目录及最多 6 层子目录，合计最多 5000 个媒体文件，按扩展名过滤，跳过隐藏项和符号链接。`name` 是相对根目录的路径，因此子目录里的文件会进入同一扁平列表。
- 超过文件数上限会标记 truncated；超过目录深度及读取子目录失败当前静默跳过。不能把列表当成完整盘点结果。
- 默认索引 TTL 为 30 秒。到期后的列表/媒体解析请求触发重扫，重扫合并但调用者等待；显式刷新可立即重扫。不是后台每 30 秒自动轮询。
- Range、路径拷贝、下载/本机定位共用白名单索引。实际文件路径还会检查 realpath、大小和修改时间。标注目前属于前端评审会话，并非共享的服务器项目数据库。

## 建议的产品模型

保留服务器原有目录组织，不要求复制或重命名实验文件。

1. **媒体根目录**：配置稳定 ID、展示名称和实际目录，可同时挂载多个实验存储位置。浏览器仅用 ID，不以绝对路径作为访问凭证。
2. **实验文件夹**：媒体区显示当前层的目录与视频，提供面包屑、返回上级、收藏目录和当前目录/全库搜索。大目录服务端分页，页面虚拟列表；不要把所有实验文件渲染成一张大列表。
3. **评审会话**：选择最多四路视频，保存顺序、备注、作者、时间与源文件版本。评审集合是对媒体的引用，同一文件可被多个评审引用，不复制原视频。

## 实现顺序

### 先解除扫描与播放的耦合

把扫描移到后台任务。HTTP Range 请求只能查询已有索引、验证请求文件并读取，不因索引 TTL 到期扫描整个根目录。后台发布完整快照，保留上一次可用结果，暴露扫描状态、更新时间、不可读目录和截断原因。文件仍在复制时标为未就绪，禁止静默把被覆盖的文件当作旧版本继续评审。

内网单实例可先用本机 SQLite 保存 roots / directories / media / scan_jobs。文件 ID 和版本分开：稳定记录 ID 供收藏与评审引用；大小/mtime、后续按需指纹记录内容版本。重启无需完整扫描才提供查询。保留现有 Range 及白名单访问边界。

### 再提供目录浏览与检索

目录和媒体查询支持 rootId、directoryId、游标分页、排序与关键词。前端逐层浏览，搜索结果同时显示实验路径，避免跨实验同名视频无法辨认。最近打开、收藏和评审集合与物理目录分别保存。

### 然后做增量更新和团队评审

本地磁盘监听作为更新提示，配合去抖增量扫描；网络存储用可配置的周期校验兜底，并保留手动刷新。Node 官方明确说明 NFS/SMB 等网络文件系统的 fs.watch 可能不可靠或不可用：
https://nodejs.org/api/fs.html#availability

落地服务器评审、注释版本及操作事件时，使用现有可信网关身份作为作者来源。注释应引用媒体版本和准确帧时间；文件被替换、移动、删除时显示状态，不自动将原评审关联到内容不同的新文件。后续出现多实例部署需求时再评估共享数据库，不先把一个内网工具拆成多个服务。

## 实施该方案时的验收建议

- 多根目录、相同文件名、多层目录及不可读子目录都有明确结果。
- 超过当前 5000 文件 / 6 层的结构不会静默丢项；分页能完整遍历索引。
- 后台扫描期间四轨播放的 Range 请求不等待全库扫描。
- 文件写入中、替换、删除和网络存储短暂断开均有可恢复状态。
- 重启服务仍能查询上次索引和保存的实验/评审引用。
