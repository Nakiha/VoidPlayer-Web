# 媒体库索引与演进

最初发布范围见 [0.1.0 发布说明](releases/0.1.0.md)。当前已实现持久化索引、后台扫描、播放器目录导航和分页、带版本的工作区/最近片源引用，以及管理后台；按访问优先的浅层检查、持久后台轮巡与有界监听已接入。真实网络存储的性能与离线恢复需要在目标挂载环境另行验收。

## 配置与数据

`mediaRoots` 接受旧的路径字符串，也支持带稳定 ID 的对象。新部署建议使用对象：

```json
{
  "mediaRoots": [
    { "id": "archive", "name": "实验归档", "path": "/mnt/archive" },
    { "id": "local", "name": "本机素材", "path": "/srv/media" }
  ],
  "indexTtlMs": 1800000,
  "indexWatch": true
}
```

相对路径按配置文件所在目录解析，ID 和路径不能重复。SMB/NFS 等存储先由操作系统挂载，再将挂载路径加入白名单。通过 `/admin` 保存根目录时即刻更新调度，新根进入后台检查，保留稳定 ID 与已有读取；直接编辑配置文件仍需重启。其他服务配置暂不热加载。

未配置任何媒体根目录的新安装可立即报告就绪，无需执行不存在的扫描任务。首次加入根目录后仍等待初次检查；移除全部根目录后恢复空库就绪状态。

独立程序使用 `--data-dir` / `VOIDPLAYER_DATA_DIR` / 系统用户数据目录，SQLite 数据库为 `library.sqlite`。源码运行可配置 `dataDir` 或传入 `--data-dir`，默认 `.run/data`。数据库必须放在服务器本地可写磁盘，不能放进只读程序目录或网络媒体盘。Docker 使用独立的 `app-data` 卷。

同一数据目录只允许一个服务写入，第二个进程启动时明确报错。独立 SQLite 锁事务在进程崩溃后由操作系统释放；重启将未结束的扫描标记为 `interrupted`，保留各目录已完成的检查和下一次检查时间，继续未完成工作。

## 身份与内容版本

- 路径字符串沿用旧算法：媒体 ID 是根目录绝对路径与相对路径的 SHA-256 前 24 位。现有工作区 URL 保持可用。
- 对象根目录使用稳定 `id` 与相对路径生成媒体 ID；同一根 ID 更换挂载路径后，已有记录仍保留原 ID。
- 索引保存旧路径算法的别名。旧配置切换为对象后，重新扫描同一路径可继续解析旧 URL；如果同时迁移目录，应先在旧路径完成一次索引，再保留数据库、固定根 ID 修改路径。
- 文件重命名视为新相对路径，不推断为原媒体；删除的记录保留为 `missing`，用于避免把历史引用误认为从未存在。
- `version` 是大小、mtime、ctime、inode 的元数据指纹，不是文件全文哈希。API 可用 `/api/media/<id>?v=<version>` 固定版本；版本不符返回 409。文件描述符打开后再次校验指纹，防止校验和读取之间替换文件。

旧的无版本 URL 仍可读取当前已索引的文件，不能据此证明历史评审与当前字节一致。播放器的新载入、最近片源和工作区导出均固定版本。导入旧工作区先核对大小与修改时间，再迁移到当前版本；这不能证明历史字节相同，只有原始记录已有版本时才能核对该版本。内容或版本不匹配会提示重新选择，并保留当前工作区。

## 后台扫描

播放器的浏览、搜索和轮询始终先返回 SQLite 中已有的目录记录，不等待 NFS/SMB 读取。响应完成后，后端只观察请求中的根目录、目录和递归范围；关键词、页码和客户端身份不创建独立扫描任务。200 与 304 响应都能续期观察，非法参数和过期分页不会入队。播放器不增加刷新按钮或扫描提示，也不自动打开媒体、seek 或抢焦点。

自动更新每次只检查一个目录当前层，发现的子目录立即进入持久队列，稍后分别检查。访问中的目录按需优先，距上次尝试至少 30 秒才再检查；`indexTtlMs` 小于 30 秒时采用更小值。同范围的多个窗口和关键词变化共用新鲜度与正在执行的任务。递归查询提升对应子树的检查优先级；没有根或目录范围的全库搜索只查询已收录记录，不触发全库遍历。观察保留 60 秒，活跃客户端的正常轮询会续期。

后台始终按最早到期的目录轮巡；最多连续执行三个前台优先任务，随后给到期的后台目录一个执行机会，防止冷门目录饥饿。默认每次目录任务结束后让出 250 毫秒，每读取八个媒体文件属性后再让出 25 毫秒；这是请求节奏控制，不是 NFS 吞吐或播放延迟保证。调度以目录为粒度，单个大目录检查期间不抢占。`indexTtlMs` 现在表示一个目录成功检查后再次进入后台轮巡的间隔，默认 30 分钟，从该目录完成时计算；已有配置值继续生效，不再代表周期性重扫全库。实际覆盖一轮所需时间还取决于目录、文件数量和 IO 延迟。

目录的检查时间和后续工作写入 SQLite schema 8；旧库升级时从已知目录和各根目录补齐任务，不改媒体 ID、版本或缓存身份。重启先提供持久化结果，并保留成功目录的冷却时间。未收录的新文件要等对应目录检查后才能被搜到，无结果不能证明磁盘上不存在。没有可靠的存储端通知时，不承诺其他机器新写入文件立即可见。

管理端显式全库刷新及内部显式子树校准仍保留递归语义，同类请求合并；全库刷新不会被局部检查吞掉，会等其结束后执行。Range 请求只查已有记录并验证目标文件，从不触发或等待全库扫描。旧列表接口也只返回已有记录，只有显式 `refresh=1` 才等待全库刷新。

检查按媒体扩展名过滤，跳过隐藏项和符号链接，没有六层或 5000 文件的收录上限。媒体及新发现的子目录每批最多 64 项写入数据库，事务不跨越文件 IO 等待；纯目录或非媒体条目循环也按批让出事件循环，不靠文件属性读取才能响应客户端。无变化的浅层检查不重写媒体记录。新写入和替换的文件先标记 `pending`，连续稳定至少一秒后才允许播放，稳定复查只安排所在目录。

浅层检查只核对当前层文件和直接子目录；确认子目录消失后，才将它的已知后代标记缺失并回收对应监听和调度条目，兄弟目录不受影响。显式递归校准仍只清理成功检查的子树。目录权限不足、超时、断线或取消时保留旧记录，并记录 `partial` / `offline` / `cancelled`。每次清理前仍验证根文件系统，不能为了减少访问而省略挂载保护。旧库尚未建立文件系统绑定时，允许继续有界寻找未改变的已知文件，但未验证文件不会成为可播放媒体，也不推断删除。

失败目录延后重试（最长一分钟，配置更小时采用配置值），持续浏览不能绕过失败退避。根离线时暂停其子目录检查，改由根探测恢复；根离线不阻止服务启动，`--init` / `--check` 仍严格检查媒体路径。操作有超时，取消及时结束扫描逻辑；底层未返回的 OS IO 会继续排空，在排空前不启动下一次检查，也不释放关闭或切换配置所需的存储所有权，避免慢 NFS 上累积残留操作。

监听只作为提示，注册于已验证的目录，不递归跟随符号链接。默认最多 512 个系统监听句柄，350 毫秒合并提示；浅层提示保留父子目录各自的工作，不把祖先检查当成已覆盖后代。内存观察范围最多 128 个，监听待处理提示有界；溢出由持久后台轮巡补漏，不提升为全库扫描。`indexWatch: false` 可以关闭监听，自动轮巡与按访问优先的检查仍工作。系统不支持监听、句柄不足或 SMB/NFS 漏报时也由轮巡覆盖，监听不是完整性保证。

管理端扫描状态保留目录数、媒体数、当前相对路径与错误数。保留最近 50 个任务，每次最多 1000 条错误详情；`scannedAt` 仍只表示显式完整根校准时间，不能将一次浅层检查冒充全根覆盖。取消会清空内存提示，自动工作至少等一个 `indexTtlMs` 后恢复，显式刷新可以立即恢复；重启或取消不承诺从目录内的精确文件位置续传。

## 接口

- `GET /api/library/browse`：`root`、`directory`、`search`、`recursive=1`、`limit`（1–200）、`offset`；立即返回当前目录的已收录媒体与子目录、扫描状态及下一页位置，后台观察该路径。递归搜索不返回目录行。
- `GET /api/library/scan`：任务状态、根目录状态和本次错误详情。响应不包含根目录绝对路径。
- `POST /api/library/scan`，JSON `{action:"refresh",rootId?}` 或 `{action:"cancel"}`：返回 202，不等待扫描；要求同源 `Origin` 与 `X-VoidPlayer-Action: scan`。
- `GET /api/media/<id>`：查询已存元数据，支持旧 ID 别名，最近片源因此不依赖当前目录页。
- 媒体清单统一使用分页 browse；不存在旧列表或 GET refresh 扫描开关。

分页响应携带 `revision`，后续页和轮询带回该值。文件或目录集合变化时返回 409，页面提示并回到第一页，避免静默跳项。无变化扫描不会使分页失效；集合变化后客户端静默重新取页并保留当前浏览范围。每页最多 60 个媒体及 60 个子目录，当前目录与全库搜索在服务端执行；本地文件/最近记录在浏览器内过滤。

## 回归覆盖与成本

扩充现有 `library-incremental`、`library-index`、`library-storage` 与 `server` 清单用例，不增加测试入口或视频素材。小型临时目录、真实 SQLite、可控时钟和 IO 门闩覆盖：浅层发现与删除、父子提示不合并、前台去重/冷却、后台公平性、重启进度、旧 schema 迁移、旧绑定的深层见证，以及超时后真实 IO 排空。HTTP 用例在目录 IO 阻塞期间独立断言缓存搜索、304 和 Range 返回；原全量校准与版本、离线保护回归继续保留。原始自动扫描策略在四目录夹具中触发 `visited=4`，新策略要求每任务 `visited=1`，保留修复前失败证明。

已有两引擎媒体库浏览器用例将新增文件检查改为无监听下的自动发现，验证现有列表自然更新；不再由测试手动刷新来替代真实接线。旧基础 UI、音频、轨道元数据及 HTTPS 播放脚本在夹具准备时显式 `list(true)`，避免依赖已移除的隐式首次扫描。65 个空子目录的门闩回归保护纯目录发现的部分提交与事件循环让出；未分批实现会在断言中失败。新增逻辑/HTTP/迁移场景使用少量文本占位文件，单次成本为数秒量级，不为功能验收增加 TB 素材或性能门禁。

## 验证边界

真实本地和网络挂载上的多轨播放、断线恢复与大型目录需要在目标环境验证，临时测试目录不能代替真实网络存储验收。生成夹具和独立发布包的验证方法见 [合成媒体库验收](generated-library-acceptance.md)。

端侧上传内容仍遵守用户显式操作约定，媒体文件始终只读。工作区与共享标注的当前行为见 [身份与分享](identity-and-sharing.md)。
