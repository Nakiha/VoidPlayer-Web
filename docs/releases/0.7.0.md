# v0.7.0 — PQ/HLG 色彩与顺带音频

相对 v0.6.1：

- 新增 PQ/HLG 高位深原始平面的自有色彩处理，覆盖首帧、播放、seek、逐帧和混合 SDR/HDR 轨道。默认仍输出可复现的 SDR 预览；可主动选择 HDR 目标，在屏幕、浏览器与浮点 WebGPU 能力满足时使用 Display-P3 扩展输出，不满足时明确降级并显示原因。
- 浏览器色彩模式新增原生 HDR 浮点桥接：浏览器 float16 Display-P3 转换后复制到浮点纹理，再由 WebGPU 呈现。当前 Chromium 路径依赖实验性的 CanvasGlobalHDRHeadroom 能力；应用只检测能力，不修改浏览器 flags。该路径增加转换/复制，不是零拷贝直通；自有色彩 HDR 不依赖此实验接口。
- UI 与 Agent 共用显示目标、假定峰值和参考白设置；工作区比较条件 v2 保存完整色彩配方，并兼容旧 SDR 条件。逐轨区分请求目标、实际输出与 SDR 降级原因；截图和缩略图保持 SDR。
- 新增按需开启的单轨顺带音频。所有轨道默认静音，点击喇叭选择出声轨道；暂停、seek、切换和移除会停止旧声音。音频只观察视频已读取的缓存，不补读媒体；支持范围内的 AAC/Opus 等仍取决于容器、浏览器解码能力和完整缓存，不承诺连续音频或采样级同步。
- 轨道信息按封装、视频和音频分组，无需解除静音即可查看已有缓存中可靠识别的音频信息；未知与不支持播放分别显示。最近工作区缩略图完整展示竖屏、横屏和方形画面，避免网格裁切。

提供 Linux x64、Windows x64、macOS ARM64 独立包及同名 SHA-256 校验文件。停止旧程序并备份完整数据目录，再完整替换程序及资源，使前端、服务端与两种 WASM 核心一起升级。保留旧包和停机备份以便回退。

## 已知限制

- 浮点输出与自动化检查不代表物理屏幕亮度已经校准；实际 HDR 亮度测量和 Windows 原设备颜色/性能验收仍未完成。假定峰值和参考白是算法参数，不能当作母版或屏幕测量结果。
- Dolby Vision/HDR10+ 动态元数据、母版静态元数据自动选择峰值和 HDR 图片导出不在本版范围内。
- CI 的 Linux headless HTTPS 性能报告保留未达实时阈值的结果，包括基线；功能门禁通过不代表所有设备、素材或多轨场景均能实时播放。macOS 有窗口 HDR 测试的通过结果不能扩大为所有平台验收。
- 音频可能因缓存缺失而中断或保持静音；声音选择不随工作区保存。小型合成素材音频回归不代表高分辨率、多轨或 WebKit 音频输出已验收。
- macOS 包暂未签名和公证。

详见 [HDR 使用与验证边界](https://github.com/Nakiha/VoidPlayer-Web/blob/v0.7.0/docs/hdr-support.md)、[顺带音频](https://github.com/Nakiha/VoidPlayer-Web/blob/v0.7.0/docs/opportunistic-audio.md)和[便携运行说明](https://github.com/Nakiha/VoidPlayer-Web/blob/v0.7.0/deploy/standalone.md)。
