# VoidPlayer 0.2.0

新增码流分析面板、首屏渐进启动、媒体库首帧缩略图与最近打开扩容；无色彩链路改动。

## 下载与启动

支持的构建及验收平台为 Linux x64（Ubuntu 24.04 / Debian 12 容器）、Windows x64（Windows Server 2022）、macOS ARM64（macOS 14）。其他系统版本与架构尚未验收。

选择对应 `.tar.gz`，核验同名 `.sha256` 后解压。包内包含独立可执行程序、网页、单/多线程 WASM、应用源码快照及许可证。运行不需要安装 Node、Bun、npm 或系统 FFmpeg。

```sh
./voidplayer --init --folder /absolute/path/to/media --data-dir /absolute/path/to/data
./voidplayer --data-dir /absolute/path/to/data --check
./voidplayer --data-dir /absolute/path/to/data
```

Windows 将 `./voidplayer` 换成 `./voidplayer.exe`。默认打开 `http://127.0.0.1:5180/`。远端使用随包 `deploy/README.md` 的 HTTPS 认证网关配置，后台运行与备份见 `deploy/operations.md`。

## 相对 0.1.1 的变化

- 码流分析面板：会话只读查询 + 面板/画布/Agent 工具；分组、视图缓存与几何抽取联动；悬停/固定/键盘检查与对数轴；偏好 v2 迁移、工作区持久化与 toast 接线；状态区展示序帧号/解码序与排名查询。
- 分析契约修正：帧率窗口口径、缓存聚合矩阵、DTS 轴覆盖、桶峰值定位、选择集身份对账、冻结交互可逆、实例 generation 盖章与旧绘制路径清理。
- 首屏渐进启动：首帧渲染即显示，GPU 预热转后台；设置样式归位，主题经 link 首屏加载。
- 解码兼容：WebKit coded 尺寸即为可见尺寸时保留 WebCodecs；HEVC conformance padding 未裁时保留 WebCodecs。
- 媒体库与首页：最近打开扩至 100 条并记录上次打开时间，首页全量滚动显示；首帧缩略图旁路生成、服务端缓存分发与清理，无图时占位不遮挡。
- 标注与顶栏：标注切换按钮锚定左下角，品牌入口改为关于；码流尾部尖峰与查询节流；标注待提交队列、GPU 呈现守卫与会话解码取消。

## 更新与恢复

停止旧程序，备份完整数据目录，再将新包解压到独立程序目录。用原 `--data-dir` 执行 `--check` 后启动；不要用包内示例配置覆盖已有配置。保留旧包和停机备份以便回退。

本版本将 `library.sqlite` 从 schema 3 升级到 schema 4（新增首帧缩略图表）；0.1.x 程序无法直接打开新索引，回退必须恢复升级前备份。`library.sqlite` 是可重建索引；`workspaces.sqlite` 保存用户工作区，不可作为缓存删除。

运行中的 SQLite 可能有 WAL/SHM 文件，备份必须在停机后复制完整目录。Docker 用户同时保留应用数据、网关配置与私有 CA 卷，升级不要执行 `docker compose down -v`。

## 已知限制

- 真实 SMB/NFS 挂载尚未实测。目录移走/恢复不验证实际网络协议、挂载行为或吞吐；文件系统类型保护无法区分同类型的另一块存储或根目录下独立的子挂载。
- macOS/Windows 程序尚未签名或公证；Windows 计划任务停止会由系统终止进程，未提供原生 Windows Service。
- 工作区保存引用和标注，不包含视频。接收方仍需能访问原服务/媒体，浏览器本地文件需要重新选择。服务器工作区无自动保存、完整版本历史或实时协作；日志也只在用户主动上传时发送。
- 远端账号由可信网关管理，尚无应用内账号管理、改密和登出界面。标注 JSON 的作者字段不是防篡改审计证据。
- 当前静音播放；浏览器管理最终色彩输出，HDR 显示尚未全面验证，WASM 当前输出 SDR。
- 吞吐测试反映当前传输路径且受系统缓存影响，不代表理论硬件上限。

三平台原生构建、启动/退出、升级/备份、HTTPS 部署与工作区持久化验证结果见 v0.2.0 标签的 GitHub Actions。浏览器回归在 macOS ARM64 归档上使用 WebKit/Chromium；不扩大声明其他平台浏览器显示效果已全面验收。下载归档和同名 SHA-256 文件后核验；包内 release.json 记录精确应用修订、Bun 与解码器来源以及资源摘要。
