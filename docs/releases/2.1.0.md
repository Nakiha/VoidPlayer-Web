# v2.1.0 — WebGPU 视频呈现与本地静态版

相对 v2.0.0：

- 视频上屏统一使用 WebGPU，移除 WebGL 与 Canvas 2D 视频回退。启动会在开放载入和工作区恢复入口前完成 WebGPU 初始化；缺少 API、adapter、device 或画布上下文时明确提示视频显示不可用，不再把隐藏源画布或旧截图当作成功呈现。`colorPipeline=legacy` 参数会被明确拒绝。
- 修复 WebGPU RGBA 资源丢失透明度、异步读回旋转尺寸未交换宽高，以及设备丢失只记录日志而不通知会话的问题。设备丢失时隐藏失效画面并暂停播放，每次初始化或色彩刷新最多自动重建一次；重建失败提示刷新或重启浏览器，恢复期间截图不会返回旧源像素。
- 新增仅使用本地文件的静态分发版（Sites）。`npm run build:sites` 生成静态项目，`npm run package:sites` 额外生成归档和校验和；播放器、WebCodecs / FFmpeg WASM 解码、多轨、逐帧、像素取样、截图、矢量标注、工作区导入导出、本机恢复和独立 Worker 深度分析均在浏览器内完成，不启动 Node 服务，也不上传视频。
- 静态版的组合导入允许一次选择工作区和原视频，继续使用现有本地媒体身份匹配、源打开、标注和布局恢复规则；导入完整版工作区时，远端片源按不可用片源跳过，已有标注保留。静态版不装配服务器身份、媒体库、文件管理、服务端工作区与分享、远端标注同步、服务管理、更新检查、本机 stdio 页面桥、日志上传及 PWA 安装。
- README 增加公开在线版入口、英文说明、功能对照和动态演示。在线版使用同一静态构建，当前为单线程 WASM，高分辨率、多轨软件解码的速度取决于设备和片源。

## 下载与升级

提供 Linux x64、Windows x64、macOS ARM64 独立包，每包附同名 `.sha256` 校验文件；最终用户无需安装 Node、Bun 或 FFmpeg。核验 SHA-256 后完整解压对应平台的包。

升级后端前停止旧程序，备份整个 `data/`，完整替换程序与随包资源，或将数据复制到新包后启动。保留旧包和停机备份以便回退，不要同时运行两个指向同一数据目录的实例。仅升级兼容前端时可使用[前端发布与回退](https://github.com/Nakiha/VoidPlayer-Web/blob/v2.1.0/deploy/operations.md#只发布前端)。

在线静态版可直接从[公开地址](https://voidplayer-local-review.akanemeguri1296.chatgpt.site/)使用，也可以按 [Sites 使用与分发](https://github.com/Nakiha/VoidPlayer-Web/blob/v2.1.0/deploy/sites.md)自行构建和托管。静态版不需要安装服务端，但工作区文件不包含视频，重新打开时仍需选择原视频。

## 支持与验证边界

- 视频显示要求浏览器和设备提供可用的 WebGPU，并通过 HTTPS 或 localhost 访问。软件 GPU、虚拟机、远程桌面或受限图形环境可能不满足要求；无法初始化时界面仍可打开，但载入和恢复视频会明确失败。需要旧 WebGL / Canvas 2D 回退路径的环境应继续使用 v2.0.0。
- 离线或本地能力限于浏览器已准备的前端和用户选择的本地文件；完整版媒体库、共享与服务器工作区仍需连接原服务。静态版不提供这些服务器功能，也不保证刷新后自动取得本地文件授权。
- 码流分析、HDR 与色彩能力仍取决于容器、编码、浏览器、GPU 和显示设备，具体组合以[码流分析说明](https://github.com/Nakiha/VoidPlayer-Web/blob/v2.1.0/docs/bitstream-analysis.md)和[色彩链路契约](https://github.com/Nakiha/VoidPlayer-Web/blob/v2.1.0/docs/color-pipeline.md)为准。自动化检查不代表实体屏幕校准或跨机器性能达标。macOS 包暂未签名和公证。
