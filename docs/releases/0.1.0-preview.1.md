# VoidPlayer 0.1.0 Preview 1

2026-09-07 发布。应用修订 `b97915d9836b32ee88f459b87898aa786ecf79dc`，独立程序版本 `0.1.0-preview.b97915d9`。

[下载发布包](https://github.com/Nakiha/VoidPlayer-Web/releases/tag/v0.1.0-preview.1)

首个独立部署预览版。网页、服务端和 WASM 已打包，运行时无需安装 Node、Bun、npm 或本机 FFmpeg。

## 下载与启动

选择与你的操作系统和架构对应的 `.tar.gz`，核验同名 `.sha256` 后解压。保持程序和 `dist/` 在同一目录：

```sh
./voidplayer --init --folder /absolute/path/to/media --data-dir /absolute/path/to/data
./voidplayer --data-dir /absolute/path/to/data --check
./voidplayer --data-dir /absolute/path/to/data
```

Windows 使用 `voidplayer.exe`。默认网页地址为 `http://127.0.0.1:5180/`。包内 README 和 `deploy/operations.md` 提供后台运行、停机备份、升级与恢复步骤；远端部署使用 `deploy/README.md` 中的 HTTPS 认证网关配置。

## 构建与验证

- GitHub Actions 原生构建 Linux x64、Windows x64、macOS ARM64，固定 Bun 1.4.2 和解码器源码/工具链版本。
- 三平台从独立产物验证空 PATH、异地工作目录、初始化/检查、HTTP/HEAD/并发 Range/中断、显式日志上传、网关身份、升级保留数据和备份恢复。
- Windows 额外验证真实独立控制台 Ctrl+C 正常退出；Linux/macOS 验证 SIGTERM 正常退出。
- Linux 使用随包 Dockerfile/Compose/Caddy 模板验证无 Node/Bun、非 root/只读运行、可信 TLS、登录与伪造身份拒绝、网页/WASM 响应头、四路并发媒体读取和重启保留 CA。
- 包内附应用源码快照、许可证、逐文件 SHA-256、应用与 FFmpeg/dav1d 构建修订及来源链接。

验证记录：https://github.com/Nakiha/VoidPlayer-Web/actions/runs/34053905776

## 预览范围与已知限制

- 验证环境为 Ubuntu 24.04 / Debian 12 容器、Windows Server 2022、macOS 14 ARM64。其他系统版本与架构尚未验收，macOS/Windows 产物尚未签名或公证。
- 当前媒体库仍是内存索引，最多 5000 项、6 层子目录；大量嵌套目录、持久化索引和后台扫描将在 roadmap 下一阶段实现。真实 SMB/NFS 存储验收尚未完成。
- 管理后台和服务器端共享评审存储尚未实现。工作区文件保存媒体引用与标注，不包含视频副本；接收方仍需能访问原媒体或重新选择本地文件。
- Windows 计划任务停止会由系统终止进程，不能等同于前台 Ctrl+C；当前未提供原生 Windows Service。
- 这是预览版，不代表 roadmap 的正式 release 验收已经完成。
