# v2.0.0 — 离线播放器与媒体库管理

相对 v1.0.0：

- 支持将播放器安装为 Web 应用。首次联网准备完成后，可离线打开本地视频和工作区；Chrome / Edge 桌面应用支持系统文件交付，Safari 提供添加到程序坞的操作指引。前端发布保留旧页面所属资源，当前评审可在更新期间继续使用。
- 重做媒体库导航与管理界面，提供挂载根目录、面包屑、列视图、可调列宽和紧凑密度。支持文件多选、拖动移动及文件管理操作；扫描状态、进度和取消反馈集中展示，文件移动后尽量复用已有缩略图。
- 更新播放器品牌图标、设置和服务管理页面，统一控件与亮暗主题反馈。改进连续缩放、平移、缩放锚点、轨道布局和标注层的交互；轨道位置可切换时间与 PTS 帧序显示。
- 改善本地与远程片源的首帧启动、渐进索引、预取和连续逐帧操作。更新固定的播放与分析核心，加入 VVC 解码优化、线程配置及资源压力反馈，并修复 HEVC QP 分析和轨道元数据短暂显示未知的问题。实际播放速度仍取决于片源、浏览器与设备。
- 在实验设置中提供临时 AI 辅助评审配对。现有本机页面可明确授权读取、视图控制和标注权限，连接受页面、有效期与撤销约束；不会自动连接或上传本地视频。源码检出方式与使用边界见[本机页面桥](https://github.com/Nakiha/VoidPlayer-Web/blob/v2.0.0/docs/local-mcp-page-bridge.md)。
- 简化 HTTP Agent 与后台功能，移除试验性的技术发现、任务中心和质量评分工作流。保留播放、码流分析、工作区、标注及对应的共享操作规则；旧试验接口不作为本版兼容承诺。
- 增加有界服务端运行日志，改进主动上传诊断报告的查看、分页和配额反馈；HTTPS 支持 HTTP/2 协商及 HTTP/1.1 回退。修复启动测试端口分配、FLV 测试素材、媒体接口方法状态码和图表格式断言。

## 下载与升级

提供 Linux x64、Windows x64、macOS ARM64 独立包，每包附同名 `.sha256` 校验文件；最终用户无需安装 Node、Bun 或 FFmpeg。核验 SHA-256 后完整解压对应平台的包。

升级后端前停止旧程序，备份整个 `data/`，完整替换程序与随包资源，或将数据复制到新包后启动。保留旧包和停机备份以便回退，不要同时运行两个指向同一数据目录的实例。仅升级兼容前端时可使用[前端发布与回退](https://github.com/Nakiha/VoidPlayer-Web/blob/v2.0.0/deploy/operations.md#只发布前端)。

## 支持与验证边界

- 离线能力限于已准备的播放器和用户选择的本地文件；媒体库、共享与服务器工作区仍需连接原服务。清除浏览器站点数据后需重新联网准备，工作区不包含视频文件。
- 码流分析的支持取决于容器、编码、配置和源帧身份，具体组合以[可执行矩阵](https://github.com/Nakiha/VoidPlayer-Web/blob/v2.0.0/scripts/bitstream-analysis-matrix.json)和[码流分析说明](https://github.com/Nakiha/VoidPlayer-Web/blob/v2.0.0/docs/bitstream-analysis.md)为准。参考图中的候选关系不代表每个块实际采用的参考。
- HDR 依赖浏览器、GPU 和显示设备；自动化检查不代表实体屏幕校准。顺带音频只观察已有视频缓存，不承诺连续音频或采样级同步。功能验证与本机性能测量分别报告，不据云端通过宣称跨机器性能达标。
- macOS 包暂未签名和公证。服务面向可信内网，用户身份表示内容归属，不是登录认证；部署和访问限制见[便携运行说明](https://github.com/Nakiha/VoidPlayer-Web/blob/v2.0.0/deploy/standalone.md)。
