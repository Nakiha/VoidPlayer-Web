# VoidPlayer 0.1.0 RC 2

首个正式版本的候选构建。此候选用于验证标签构建和 Release 草稿流程；真实 SMB/NFS 媒体存储验收尚未完成，不代表正式版本已通过全部验收。

## 下载与启动

支持的构建及验收平台为 Linux x64（Ubuntu 24.04 / Debian 12 容器）、Windows x64（Windows Server 2022）、macOS ARM64（macOS 14）。其他系统版本与架构尚未验收。

选择对应 `.tar.gz`，核验同名 `.sha256` 后解压。包内包含独立可执行程序、网页、单/多线程 WASM、应用源码快照及许可证。运行不需要安装 Node、Bun、npm 或系统 FFmpeg。

```sh
./voidplayer --init --folder /absolute/path/to/media --data-dir /absolute/path/to/data
./voidplayer --data-dir /absolute/path/to/data --check
./voidplayer --data-dir /absolute/path/to/data
```

Windows 将 `./voidplayer` 换成 `./voidplayer.exe`。默认打开 `http://127.0.0.1:5180/`。远端使用随包 `deploy/README.md` 的 HTTPS 认证网关配置，后台运行与备份见 `deploy/operations.md`。

RC 1 的原生验收被旧脚本中仅接受 preview 版本的断言阻断，未创建 Release；RC 2 改为核对完整版本和修订，重新运行三平台验收。

## 相对 Preview 1 的变化

- 媒体库改为 SQLite 持久化索引，支持多个稳定根目录、嵌套目录、分页、目录/全库搜索和后台扫描；监听提示配合周期校准，离线保留索引。
- `/admin` 提供可信身份管理、根目录配置与扫描控制、机器与连接状态、诊断日志检视和主动吞吐测量。
- 设置中可以主动保存服务器工作区；按用户归属隔离，版本冲突保留本地会话并支持另存副本。管理员可以检视、改名、下载和删除工作区。
- GitHub Actions 在三平台原生构建和测试后汇总同一修订的产物；标签版本与程序版本一致，包内提供逐文件摘要、运行时版本和解码器来源。

## 更新与恢复

停止旧程序，备份完整数据目录，再将新包解压到独立程序目录。用原 `--data-dir` 执行 `--check` 后启动；不要用包内示例配置覆盖已有配置。保留旧包和停机备份以便回退。

`library.sqlite` 是可重建索引；`workspaces.sqlite` 保存用户工作区，不可作为缓存删除。运行中的 SQLite 可能有 WAL/SHM 文件，备份必须在停机后复制完整目录。Docker 用户同时保留应用数据、网关配置与私有 CA 卷，升级不要执行 `docker compose down -v`。

## 已知限制

- 真实 SMB/NFS 挂载的端到端评审、离线重连验收仍待完成；临时目录模拟和 CI 不替代真实存储验收。
- macOS/Windows 程序尚未签名或公证；Windows 计划任务停止会由系统终止进程，未提供原生 Windows Service。
- 工作区保存引用和标注，不包含视频。接收方仍需能访问原服务/媒体，浏览器本地文件需要重新选择。服务器工作区无自动保存、完整版本历史或实时协作；日志也只在用户主动上传时发送。
- 远端账号由可信网关管理，尚无应用内账号管理、改密和登出界面。标注 JSON 的作者字段不是防篡改审计证据。
- 当前静音播放；浏览器管理最终色彩输出，HDR 显示尚未全面验证，WASM 当前输出 SDR。
- 吞吐测试反映当前传输路径且受系统缓存影响，不代表理论硬件上限。

本候选的三平台、原生启动/退出、升级/备份、HTTPS 部署与工作区持久化验证结果，以对应标签的 GitHub Actions 运行结果为准。正式发布前继续完成项目 Roadmap 剩余验收。
