# v0.3.0 — 可恢复的评审现场与资源协调

- 本机工作区检查点与显式恢复入口；缺失片源保留待重新关联轨道、标注和偏移。服务器仍显式保存。
- 工作区记录色彩、解码偏好及呈现契约；兼容旧文件并提示缺失条件。
- reference 未保存解码偏好时默认硬件优先；FLV（含非标 HEVC）接通 WebCodecs 原始平面读回和软件首帧核对，失败按阶段回退 WASM，保留已有软件选择。
- 服务端帧索引 POST/GET 重工作移至单任务 Worker；提交前重新验证媒体和清理 epoch；便携程序内嵌 Worker。
- 缩略图本地容量/数量 LRU、可见图片 Object URL 引用生命周期、本地 recipe 版本键。
- 会话共享应用帧/读回/派生资源预算，压力下减少预取并停止派生任务，必需评审帧不因软预算降精度或丢弃。
- 校准架构文档：渐进索引及追赶状态已存在。

范围：256 MiB 是应用可见资源的协调目标，不是进程/GPU 硬上限；保存比较条件不等于跨设备逐像素一致。自动检查点是周期性的本机尽力保存，浏览器清理站点数据会删除它；需要交接时请显式保存/导出。

验证记录见 [v0.3.0 验证](../verification-0.3.0.md)。
# 追加：统一媒体入口与 TS 定位

- 本地/远程共用字节识别、解码偏好、失败阶段回退和 reference 准入。非 MP4 容器不再先尝试 MP4 包索引器；上屏继续由 presenter 统一负责。
- 固定新的上游 core 修订，TS 包扫描保留关键帧字节锚点与 DTS，seek 从附近 GOP 解码；保留精确 PTS 校验和保守回扫。
- 轨道信息及日志明确显示索引/定位能力，并记录实际解码帧数与回扫次数。
- 新增长 TS、改名文件、本地/Range、H.264 TS/MP4 浏览器回归脚本并接入 CI。HLG 回归样片由 CI 用 ffmpeg 从 H.265 样片稳定合成（上游稀疏检出不含该文件）；详见验证记录。
