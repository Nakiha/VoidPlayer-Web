# 测试与 CI 整改验证

基线：`52a5e268`。本次修改测试执行、报告、分析场景职责和准入文档；播放、解码、呈现及评分生产实现未修改。

## 改动与覆盖

- 复用现有 runner/fixture 输出构建、准备、执行和阶段成本，成功与失败均保留；阶段证据按本次启动时间围栏，只有顶层 CLI 可发布 job 摘要。辅助报告错误不改变原门禁结果。
- 无媒体/core/构建/工具依赖的独立 source 选择使用两个 worker。逐项进程、临时目录和 watchdog 保留；原子发布结果，全部完成前不能通过，取消等待活动子进程退出后记录剩余取消项。媒体、浏览器和依赖阶段保持串行。
- 分析场景把输入职责与通用 UI 交叉执行分开。两种输入的真实身份、opt-in、缓存、显示零新增分析、300 AU、共享视口及工作区恢复保留；完整通用交互矩阵在媒体库数据上执行一次。两种浏览器及全部编码/容器/深度/解码策略矩阵保留。
- 日常门禁检查必需行为、引擎、环境与完整依赖图，取消固定入口总数检查。新增/扩充场景按行为缺口、独立预期、必要环境和成本审查，规则与迁移映射见 [验证说明](../testing.md)。

原始结果目录：`.run/test-suites/ci-remediation-source-{1,2}/`、`ci-remediation-baseline-webkit/`、`ci-remediation-core-browser-final/`。迭代失败保留在 `ci-remediation-after-webkit/` 和 `ci-remediation-core-browser/`：分别暴露图表回调作用域及批量读取图表选择的陈旧快照问题；修复后分别复测，并重新完成 33 项核心套件，不覆盖失败证据。

本轮验证代码净增约 200 行，集中于有界调度、成本报告及失败/取消回收证明；Node 与日常浏览器登记执行单元数保持不变。收益来自减少重复交叉执行和串行等待，代码维护成本继续通过准入与行为映射审查。
