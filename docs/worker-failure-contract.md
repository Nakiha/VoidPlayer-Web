# Worker failure and ownership contracts

Issue #64 P2-C preserves independently owned workers and their different failure scopes. This matrix describes the source contracts, not a claim that every injected failure has passed. A shared transport is not required to close the identified gaps.

The new `node-worker-rpc` injections prove browser and Node deserialization failures reject outstanding/future requests, release optional byte waits, publish a single index error after ready, invoke teardown once and close one delivered late frame once. Existing Node crash/exit, timeout, explicit cancellation, transferred-buffer, incremental index ordering and optional-audio assertions remain. A new postMessage failure case also proves an independently owned healthy video RPC survives.

This consolidated delivery includes the reviewed native/audio/video lifecycle changes and the already-merged local-analysis, thumbnail and server Worker fixes. The full P2-C matrix remains incomplete: nativeYuvSource converter failure/late-resource coverage and final integrated acceptance are still pending. There is no new common framework and no change to normal frame decoding, index wire layouts or playback performance limits.

The follow-up teardown slice settles pending promises and terminates the worker before rethrowing index/owner hook exceptions. The original latched RPC failure remains the rejection cause; Direct terminate calls rethrow callback failures, with an AggregateError when both hooks throw. Inside call() a synchronous postMessage failure rejects the original request before a hook rethrow; that Promise executor can absorb the rethrow. The immutable terminationCallbackErrors diagnostic getter retains at most the two hook failures in either path, so callers can inspect them after the original request settles. No automatic log upload or cross-worker notification is added. Browser-stub negatives prove a throwing index or ownership hook cannot strand pending work after failure is latched. This does not complete the other clients’ lifecycle matrix.

Native metadata lifecycle evidence uses browser-interface event injection and a real Node worker_threads instance with manually emitted messageerror. This exercises the installed deserialization-failure path; it does not manufacture an actual undecodable transport payload. Pending requests, AbortSignal listeners, repeated close and real Node exit listener counts are observed, and an independently owned healthy metadata client remains usable. Existing real append/transfer, query/statistics and cancellation regressions remain mandatory. No decoded frame or playback instance is transferred through this client.

The controlled Node-like EventEmitter keeps listeners when its termination Promise settles, unlike Node 24 worker exit cleanup. Separate resolve and reject cases require client callbacks to remain before settlement (including the late error handler), then require exactly the pre-existing external callbacks to remain afterward. Deleting the Node detach implementation makes both cases fail. The real Node exit zero-count assertion alone is not evidence that client detach ran. These controlled cases preserve the explicitly synthetic event/termination boundary.

## Cached audio reverse channel

The browser-only cached audio client keeps generation pushes and reverse byte/window observations separate from playback RPC. It owns no request deadlines or pending map: outstanding lookup promises remain with their cache provider, and their late completion is checked against the current worker before transfer. Mute, failure and explicit stop detach all three event properties and terminate that disposable parser once. Enabling audio again may create a fresh parser; old callbacks cannot stop or feed it.

`node-cached-audio-client` injects the installed browser event handlers using a Worker double. Original code fails messageerror teardown and produces unhandled rejections on deferred byte/window postMessage failure; fixed code passes seven cases. Actual structuredClone transfer proves successful byte copies detach, while late/failed replies remain locally owned. Other cases cover init/query post failure, lookup misses, disable, recovery, old pushes and old error events. These are browser-contract injections, not a real malformed deserialization payload or new Node audio-worker support. Existing real audio/playback regressions remain separate CI checks.

## Native raw-plane converter lifecycle

The `nativeYuvSource` pool correlates each copy with a private request ID. A picture's copy-error reply rejects only that picture and permits reuse; a Worker error/messageerror, malformed reply or failed post latches a failure for this converter, terminates its owned pool, and rejects active jobs and slot/input waiters. Other wrappers and the upstream source remain independently owned. Explicit disposal cleans the pool before invoking an owned upstream dispose hook, so a throwing hook cannot strand pending work. No additional request deadline, decoder fallback or color/layout policy is introduced.

A successful post transfers native-frame ownership to the Worker; failed posts close the untransferred sender resource. The original decoded sample closes once. Yielded YUV buffers belong to callers until close, then may be transferred for reuse. Old replies cannot fulfill a new job. Cancelled/disposed upstream reads reject promptly and close a late returned sample; iterator return does not wait for a held next input. Tests inject installed browser-like handlers and use actual ArrayBuffer transfer for recycled storage; native VideoFrame ownership in Node doubles remains a simulated boundary, with real readback checks kept separate.

Review completion: copy IDs are positive, contiguous per Worker channel; only previously issued older IDs are duplicate replies. Full geometry/plane validation occurs before fulfilling a job and invalid transport/layout replies latch pool failure. Streaming factories are lazy and recheck terminal state before upstream next. A local iterator return signals cancellation before the native async-generator queue, including the first input/copy wait; late copies retain an explicit close owner without terminating a different iterator's source pool. These streaming boundaries were pre-existing incomplete cancellation behavior.
