# Worker failure and ownership contracts

Issue #64 P2-C preserves independently owned workers and their different failure scopes. This matrix describes the source contracts, not a claim that every injected failure has passed. A shared transport is not required to close the identified gaps.

| Client | Correlation / flow | Error, exit, messageerror | Cancellation / pending | Late resources and transfer ownership |
| --- | --- | --- | --- | --- |
| `WorkerRpc` (FFmpeg/packet video) | Request ID and command map; incremental ready/batch/complete/error are separate from a settled init call; cached bytes/audio are optional side channels | Browser error and Node error/exit terminate this worker and reject all pending. This slice adds both messageerror branches to the same terminal path. | Explicit teardown, deadline and postMessage failure terminate this RPC; pending timers are cleared, byte waits settle quietly, ready-but-incomplete index emits one terminal error. | Caller-owned recycle buffers transfer to the worker; returned frame resources transfer to the caller. Message handling remains reachable to close a late transferred frame after cancellation. |
| Native metadata analysis | ID/command map, no decoded frames on this channel | Browser error/messageerror and Node error/exit close this independent client. The follow-up native-client slice adds Node messageerror to the same independent terminal path. Browser listeners detach synchronously; Node client listeners detach once termination completes, retaining the error handler until then so late EventEmitter errors remain handled. | Per-request AbortSignal sends cancel and cleans pending/timer/abort listener; postMessage failure rejects only that request. Client close settles every request. | No playback resources cross this channel. Worker event listener detachment remains to audit. |
| Local bitstream analysis service | Independent job worker; chunks require consumer ACK; snapshot/index/cache are reverse requests | Error path terminates the job. messageerror and reverse-channel postMessage exceptions need dedicated injection coverage. | Task completion/cancellation terminates only this analysis worker and removes operation abort handling. | Results are analysis metadata; playback cursor and presented resources stay separately owned. Streaming must retain ACK backpressure. |
| Cached container audio | Generation-tagged pushes and reverse byte/window observations | Failure stops only the audio parser. messageerror and asynchronous reverse-reply exceptions need injection coverage. | Disable/mute tears down the worker; optional audio failure must not reject video RPC. | A returned byte copy transfers to the audio parser; video frame resources are never transferred. |
| Thumbnail pixels | One result per accepted, expiring offer | Error and postMessage failure finish with no thumbnail. messageerror still needs a dedicated branch and test. | Offer expiry finishes once and terminates this disposable worker. | Pixel storage is transferred after ownership acceptance; no returned VideoFrame. Expiry and late results must remain idempotent. |

The new `node-worker-rpc` injections prove browser and Node deserialization failures reject outstanding/future requests, release optional byte waits, publish a single index error after ready, invoke teardown once and close one delivered late frame once. Existing Node crash/exit, timeout, explicit cancellation, transferred-buffer, incremental index ordering and optional-audio assertions remain. A new postMessage failure case also proves an independently owned healthy video RPC survives.

This slice does not complete the full P2-C acceptance matrix. Remaining work includes native/bitstream/audio/thumbnail differential injections, callback exceptions during teardown, and deliberate listener ownership/detachment without losing late transferable disposal. There is no new common framework and no change to normal frame decoding, index wire layouts or playback performance limits.


Native metadata lifecycle evidence uses browser-interface event injection and a real Node worker_threads instance with manually emitted messageerror. This exercises the installed deserialization-failure path; it does not manufacture an actual undecodable transport payload. Pending requests, AbortSignal listeners, repeated close and post-termination transport listeners are checked, and an independently owned healthy metadata client remains usable. Existing real append/transfer, query/statistics and cancellation regressions remain mandatory. No decoded frame or playback instance is transferred through this client.
