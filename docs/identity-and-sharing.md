# 用户、访客与工作区分享

## 身份创建时机

用户身份只在 `POST /api/identity` 明确填写用户名时创建。`GET /api/health`、媒体浏览、工作区读取、标注读取与管理页面读取均不创建用户，也不补写身份 cookie。

首次打开播放器或管理页，cookie 缺失、无效或对应用户不存在时，展示选择界面：选择已有用户、填写用户名、以访客继续。界面说明可在设置 → 用户中修改。访客是 `guest-<UUID>` cookie，显示名统一为“访客”，不插入 users 表；刷新与服务重启后沿用 cookie。访客保存的数据仍以其访客 ID 记录归属。清除 cookie 后无法自动找回访客身份。

身份接口接受 `{name:string}`、`{id:string}` 或 `{guest:true}`。写入工作区、标注前必须显式选择身份；HTTP agent 应先调用该接口并保存 cookie。健康检查不代表登录。名字沿用可信内网的自主声明模型，不是身份证明；同名表示切换到已有身份，不迁移另一个身份的历史数据。

数据库 v3 为旧用户增加 kind：旧版自动生成格式 `用户-xxxxxxxx` 迁移为访客，保留 ID 和所有历史引用，不删除数据、不按前缀持续推断新名字。已有用户列表仅返回 named；旧访客仍可用原 cookie 打开自己的工作区，明确填写名字可保留其 ID 升级。这个一次性迁移无法区分过去手工填写的完全同格式名字，可通过重新设置用户名恢复。

## 分享契约

添加视频右侧的“分享”按钮和 WebMCP `share_workspace` 使用同一个操作：

1. 点击时立即捕获独立 snapshot，包括媒体引用、轨道顺序/偏移、暂停还原位置、标注及缩略图、视口缩放/平移/对比方式和工具区布局。
2. 检查并固定所有媒体库引用的版本。浏览器本地文件无法跨客户端重新打开，因此拒绝生成包含本地引用的分享；不隐式上传视频。
3. `POST /api/shares` 保存独立不可变文档到 workspaces.sqlite 的 workspace_shares 表，返回 ID 和 `/?share=ID` 路径。允许访客分享，不创建用户。请求受现有同源写入检查和 32 MiB 文档限制约束。
4. 创建期间禁用按钮并显示进度图标；成功后复制链接并显示顶部 toast。剪贴板不可用时仍显示已创建链接供手动复制，不重复创建快照。
5. `GET /api/shares/ID` 无需身份即可读取；网页完成首次用户/访客选择后，通过原有工作区导入流程原子还原。快照在本地编辑，修改不会回写旧链接。普通可变工作区的更新/删除接口不能修改分享。

分享不会保存播放中的解码队列，也不会自动开始播放；还原到记录的时间。跨设备窗口大小不同时，布局按现有响应式约束显示。同一服务器用不同域名访问时，把同源媒体引用映射到接收者访问的域名；外部媒体库引用保留原地址。接收者必须能访问相关媒体服务。源文件被删除或版本发生变化时明确失败，不替换成同名文件。

分享记录持久保存，服务重启不会使链接失效。本轮不对用户数据或分享记录实施自动清理。已有 `?workspace=ID` 仍是可变工作区入口，与不可变 `?share=ID` 分开。
